# 実験を 1 本足す手順

**宣言は 1 箇所です**（`src/rc_basics_lab/experiment/catalog.py` の `CATALOG`）。

かつては同じ事実を 3 箇所に書いていました（`run_0N.py` / `main.py` の
`EXPERIMENTS` / `Makefile` の `figures-0N`）。食い違いをテストが事後に照合して
いましたが、**照合が要る形そのもの**がコストでした（D-125）。

## 1. 設定 dataclass を書く

`src/rc_basics_lab/config/<name>.py` に実験専用の dataclass を置きます（D-13）。
**01 の `ExperimentConfig` に相乗りさせない** —— 相乗りさせると YAML の未知キー
検査（D-09）と配線テストの被覆が同時に壊れます。

## 2. パイプラインを書く

`src/rc_basics_lab/experiment/<name>_pipeline.py` に
`run_and_report_<name>(config, out_dir)` と `<NAME>_ARTIFACTS` を置きます。

## 3. カタログに 1 エントリ足す

```python
ExperimentSpec(
    number="06",
    name="06_something",
    results_dir=RESULTS_DIR / "06_something",
    artifacts=SOMETHING_ARTIFACTS,
    budget_s=900.0,
    variants={MAIN: _run_06},
)
```

`_run_06` は「設定を読んでパイプラインへ渡す」だけの関数です。設定の型は実験
ごとに違うので、**読み込みを関数の内側に閉じる**ことでカタログが単一の型で
並びます。

## 4. 設定 YAML を置く

`experiments/06_something/config.yaml`。ディレクトリ名の接頭辞が `number` と
一致していることを `tests/test_main.py` が検査します。

## 触らない場所

| | なぜ |
|---|---|
| `Makefile` | `figures-%` のパターンルール 1 本が全実験を賄う |
| `main.py` | カタログを読むだけで、実験を知らない |
| run スクリプト | 存在しません（`main.py --experiment 06`） |

## 走らせ方を増やすとき

真偽フラグ（`--length-sweep` のような）は足さないでください。増えるたびに
`parse_args` と `main` の `if` が**両方**伸びます。`variants` に 1 行足します:

```python
variants={MAIN: _run_06, "sensitivity": _run_06_sensitivity}
```

```bash
uv run python main.py --experiment 06 --variant sensitivity --results
```

## 手元で回す

```bash
uv run python main.py --experiment 06                  # scratch/06_something へ
uv run python main.py --experiment 06 --preset quick
uv run python main.py --experiment 06 --set n_replicates=1
uv run python main.py --experiment 06 --results        # results/ へ (= make figures-06)
```

**既定が `scratch/` なのは意図的です。** `--out` を忘れた実行が `results/` の
成果物を黙って上書きしないようにしています。
