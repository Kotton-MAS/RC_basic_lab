# 汎用基盤を別リポジトリへ切り出す

**この手順は測ってあります。** `tests/test_core_extraction.py` が毎回、汎用側
だけを一時ディレクトリへ複製して「連載側が 1 バイトも無い状態で import して
実験を 1 本回す」ことを確かめています。手順書が嘘になったら CI が赤くなります。

## いま切り出せるもの（実測）

| | 本数 | 行数 |
|---|---|---|
| 汎用 | 53 | 10,894 |
| 全体 | 132 | 33,698 |

```
tasks/ reservoir/ readout/ diagnostics/ datasets/
metrics.py metrics_detection.py metrics_significance.py
seeds.py split.py types.py cli.py overrides.py
experiment/{rows_csv,diagnostics_rows,capacity_bounds}.py
```

同梱データ（`datasets/manifests/*.csv`）も一緒に運びます。**`.py` だけ複製すると
`FileNotFoundError` になります**（実測。だから smoke test は import だけでなく
実行まで見ています）。

## 手順

### 1. 履歴ごと切り出す

```bash
# 汎用側のパスだけを残した履歴を作る (元のリポジトリは触らない)
git clone . ../rc-lab && cd ../rc-lab
uv tool run --from git-filter-repo git-filter-repo \
  --path src/rc_basics_lab/tasks \
  --path src/rc_basics_lab/reservoir \
  --path src/rc_basics_lab/readout \
  --path src/rc_basics_lab/diagnostics \
  --path src/rc_basics_lab/datasets \
  --path src/rc_basics_lab/metrics.py \
  --path src/rc_basics_lab/metrics_detection.py \
  --path src/rc_basics_lab/metrics_significance.py \
  --path src/rc_basics_lab/seeds.py \
  --path src/rc_basics_lab/split.py \
  --path src/rc_basics_lab/types.py \
  --path src/rc_basics_lab/cli.py \
  --path src/rc_basics_lab/overrides.py \
  --path src/rc_basics_lab/experiment/rows_csv.py \
  --path src/rc_basics_lab/experiment/diagnostics_rows.py \
  --path src/rc_basics_lab/experiment/capacity_bounds.py \
  --path docs/guide
```

`git subtree split` ではなくパス指定にするのは、汎用側が 1 つのディレクトリに
まとまっていないためです（`experiment/` に 3 本残っています）。

**このリストは手で書き写さないでください。** 実体は
`tests/test_core_series_boundary.py` の `CORE_PACKAGES` /
`CORE_MODULES` / `CORE_EXPERIMENT_MODULES` です。切り出す日には
そこから生成してください:

```bash
uv run python -c "
import sys; sys.path.insert(0,'tests')
from test_core_series_boundary import _core_files, PACKAGE_ROOT
for p in sorted(_core_files()):
    print('  --path src/rc_basics_lab/' + str(p.relative_to(PACKAGE_ROOT)))"
```

### 2. パッケージ名を決める

**このタイミングで改名します。** いま改名していないのは、`rc_basics_lab` を含む
ファイルが 231 件あり、切り出す前に変えても後に変えてもコストが同じだからです
（D-126）。

```bash
git grep -l rc_basics_lab | xargs sed -i '' 's/rc_basics_lab/rc_lab/g'
git mv src/rc_basics_lab src/rc_lab
```

連載の原稿が `rc_basics_lab` を引用している場合は、原稿側も直す必要があります。

### 3. 持っていくもの / 置いていくもの

| 持っていく | 置いていく |
|---|---|
| `docs/guide/` | `docs/series/` `docs/plans/` `docs/process/` |
| `.claude/decisions/` のうち汎用の決定 | 記事固有の決定（D-29 / D-39 / D-116 など） |
| `tests/` のうち汎用側を測るもの | `tests/test_experiment_*.py` `tests/test_config_wiring_*.py` |
| `pyproject.toml`（依存は同じ 4 つ） | `Makefile` の `figures-%` `results/` `experiments/` |

`.claude/decisions/` は **1 決定 1 ファイル**（D-121）なので、`guard_test` が
どちらのテストを指しているかで機械的に振り分けられます。

### 4. 元のリポジトリ側

```toml
# pyproject.toml
dependencies = ["rc-lab>=0.1", "matplotlib", "numpy", "pyyaml", "scipy"]
```

`config/` の再エクスポートを新パッケージからの import に差し替えます。
**差し替えるのはここだけ**です（課題の生成パラメータは既に `tasks/` にあり、
`config/` は再エクスポートしているだけなので）:

```python
# config/experiment01.py
from rc_lab.tasks.mackey_glass import MackeyGlassConfig   # was rc_basics_lab.tasks...
```

### 5. 確かめる

```bash
cd ../rc-lab && uv sync && uv run pytest -q     # 汎用側が単体で緑
cd -          && make ci                         # 連載側が新しい依存で緑
make figures-01 && uv run pytest tests/test_artifact_invariance.py
```

**最後の 1 行が本番です。** 切り出しで成果物が 1 バイトでも動いたら、それは
切り出しではなく変更です。

## 切り出す前に確かめること

```bash
uv run pytest tests/test_core_series_boundary.py tests/test_core_extraction.py -q
```

この 2 本が緑なら、上の手順は通ります。赤いときは**手順ではなく境界が壊れて
います** —— 汎用側から連載側を import した箇所を直すのが先です。
