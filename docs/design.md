## 2. 未確定事項への回答（仕様 §3 の転記）

### 2.1 Mackey-Glass

τ=17, β=0.2, γ=0.1, n=10 / RK4 h=0.1 / サンプリング間隔 Δt=1.0（10ステップごと）/
積分バーンイン 1000 サンプル破棄 / 有効長 8000 / washout 200 /
残り 7800 を 0.5:0.15:0.35 = 3900/1170/2730 に連続分割。

- τ=17 は Farmer (1982) 以来のカオス域標準値で、RC ベンチマークの事実上の既定
- Δt=1.0 は Lukoševičius の実践ガイド系の慣例
- 分割比は、検証で alpha と `n_lags` を選ぶ余地を残しつつテスト区間を最大化する配分
- 時系列なのでシャッフルせず連続区間で切る

### 2.2 遅延パリティ

既定は `n_bits=2, delay=1`（`y[t] = u[t-1]·u[t-2]`、`u[t]` は ±1 の i.i.d.）。
副条件として `n_bits=3, delay=2` も設定リストに併記する。

**なぜこの設定なら「線形は解けない」が保証されるか。** `u[t] ∈ {-1,+1}` i.i.d. のとき、
任意の `k` について

```
E[y[t]] = 0,   E[y[t]·u[t-k]] = E[u[t-1] u[t-2] u[t-k]] = 0
```

（`k ∉ {1,2}` なら独立3変数の積で期待値0、`k ∈ {1,2}` なら `u² = 1` により残る1変数の
期待値が0）。つまり `{1, u[t], u[t-1], …, u[t-k]}` の張る線形空間に対して目標が
**厳密に直交する**。母集団最適な線形予測子は恒等的に 0 であり、NRMSE → 1.0、
符号正解率 → 0.5 になる。

重要な副産物として、遅延線 `[1, u[t..t-k]]` も同じ理由で失敗する。これは
「最も安い対照は遅延線」という連載の芯に対して、「必要なのは記憶ではなく非線形性」
という最も鮮明な実演になる。一方 tanh リザバーは状態内に `u[t-1]u[t-2]` 型の交差項を
生成するため解ける（古典的な temporal XOR / delayed parity 課題）。

数値受け入れライン（5シード平均、テスト区間）:

- 線形・遅延線: `NRMSE >= 0.95` かつ `sign_accuracy <= 0.60`
- ESN: `NRMSE <= 0.50` かつ `sign_accuracy >= 0.90`
- 両者の NRMSE の ±1σ 区間が重ならない

### 2.3 誤差指標

NRMSE に統一する。定義は `RMSE / std(y_true)`（ddof=0、評価区間の目標系列の標準偏差で
正規化）。NRMSE = 1 が「平均予測と同等」を意味するため、パリティ課題の失敗判定が
解釈可能になる（範囲正規化では 1 に意味が無い）。CSV には `rmse` / `nmse`(= NRMSE²) /
`nrmse` / `sign_accuracy` を併記する。`nmse` の併記はサイクル03 の先行研究比較への前倒し。

`sign(0)` の扱いは `+1` に固定する（それでも正解率は約0.5）。
`std(y_true) == 0`（定数目標）では NRMSE が定義できないため `ValueError` で即座に失敗させる
（0 除算で inf/nan を返すと下流の集計が静かに壊れる）。

### 2.4 スペクトル半径の算出

`numpy.linalg.eigvals`（密行列・決定論的）で算出する。ARPACK は反復初期値で微小に揺れ
再現性が落ちるため、N ≤ 1000 の本連載規模では密で押す。

## 3. 乱数ストリームの分離

`reservoir` / `task` / `split` の3ストリームを `numpy.random.SeedSequence` の
`spawn_key = (ストリーム番号, レプリケート番号)` で分離する。1ストリームのシードを
変えても他ストリームの乱数列はバイト単位で不変であり、「リザバーだけ変えたときの分散」
が測れる。`spawn_key` のストリーム番号（reservoir=0, task=1, split=2）は永続化された値で、
変更すると既存の結果が再現しなくなる。

## 4. 設定層

未知キーは `ConfigError` で即座に失敗させる。本サイクルは十数個のパラメータを YAML 化
するため、キーのタイプミスが黙って無視されると「設定したのに効いていない」実験結果が
生まれる。ローダは frozen dataclass のフィールド型から再帰的に構築するので、
セクションを増やしても未知キー検出は自動で効く。

## 5. 診断層のインターフェース

```
Diagnostic: (X, u=None, y=None, *, ctx: DiagnosticContext | None) -> DiagnosticResult
```

位置引数は要件書の literal な `f(X, u, y)` を保ち、拡張は
`DiagnosticContext` への**既定値つきフィールド追加**1点に集約する。サイクル02 の ESP は
2軌道を要するが、これを第2位置引数にすると MC / IPC と署名が割れる。
`ctx.companion_states` に逃がすことで、02 の ESP・条件付き Lyapunov、04 の Lyapunov 時間
正規化（`ctx.dt`）、03 のシャッフルサロゲート（`ctx.seed`）がすべて署名変更なしで乗る。

`diagnostics` は ESN クラスに一切依存しない（`import` レベルでも参照しない）。
外部で生成した任意の状態系列 `X` に適用できることが、`memristor-rc-lab` への移植性の
実体であり、テストで機械的に守る。

## 6. リザバー層（ESN）と読み出し層

### 6.1 更新式

```
x[t] = (1 - a) * x[t-1] + a * tanh(W_in @ [1; u[t]] + W @ x[t-1] + noise)
```

`W_in` は密で shape `(N, 1+D_in)`。先頭列（定数入力 1）は `U[-bias_scale, bias_scale]`、
残りの入力列は `U[-input_scale, input_scale]` から引く。`W` は密度 `density` の疎構造を
密行列として保持し、`numpy.linalg.eigvals` で実測したスペクトル半径で割ってから
`spectral_radius` を掛けて正規化する（実測値との一致を rtol 1e-10 でテストしている）。

`step` と `run` をサイクル01 の時点で両方公開する。`x0`（02 の2初期状態）、
`state_noise`（04 のノイズ注入）、`step`（04 の閉ループ）を先に配線しておくことで、
02/04 で公開 API を変更せずに済む。`run` は `step` の逐次呼び出しと**ビット単位で同一**
であり（入力射影をまとめて計算する最適化をあえて入れていない）、閉ループに切り替えた
瞬間に軌道が変わる事故を防いでいる。

### 6.2 構造ハイパーパラメータの既定値（検証で調整しない・D-08）

| 用途 | N | ρ | leak | input_scale | density |
|---|---|---|---|---|---|
| Mackey-Glass | 200 | 0.9 | 0.3 | 0.5 | 0.1 |
| 遅延パリティ | 200 | 0.9 | 1.0 | 1.0 | 0.1 |

- MG は連続系をサブサンプルした滑らかな系列なので、漏れ率を下げて（0.3）状態の
  時定数を入力の時定数に合わせる。実測でも leak 0.1 / 1.0 で状態のラグ1自己相関が
  0.93 / 0.07 と大きく変わる（`test_leak_rate_changes_state_autocorrelation`）
- パリティは各ステップが独立な ±1 の離散入力なので、状態を平滑化する理由がなく
  leak = 1.0。`u[t-1]·u[t-2]` の交差項を tanh の非線形項として十分な振幅で出すため
  input_scale も 1.0 に上げる
- ρ = 0.9 は ESP を保つ古典的な既定値（サイクル02 でこの前提自体を測る）
- `bias_scale` の既定は 0.1。仕様は `bias_scale` の作用点を定義していなかったため、
  「`W_in` の先頭列だけに適用する」と決めた。定数入力の寄与が入力の寄与を上回ると
  tanh が飽和側に張り付くので、`input_scale` より小さい値を既定にしている

`ESNConfig` の dataclass 既定値は MG 用の組に一致させてある。実験で使う値は
サイクル01 の YAML に明示する（既定値に依存した「暗黙の設定」を残さない）。

### 6.3 設計行列 — 3ベースラインを分ける唯一の場所

| 手法 | `FeatureSpec` | 列 | 列数 | `first_valid` |
|---|---|---|---|---|
| 線形 | `PassthroughSpec()` | `[1, u[t]]` | `1+D` | 0 |
| 遅延線 | `DelayLineSpec(n_lags=k)` | `[1, u[t], …, u[t-k]]` | `1+D(k+1)` | `k` |
| リザバー | `ReservoirSpec()` | `[1, u[t], x[t]]` | `1+D+N` | 0 |

3手法の違いは `FeatureSpec` の差**だけ**であり、`build_design_matrix` という単一の
呼び出し口を通る。内部でも仕様を `_Layout`（どのラグの入力を並べるか / 状態を使うか）
に正規化してから組み立て経路を1本に合流させており、手法ごとの分岐は `_layout_of` の
`match` 1か所しかない。

`first_valid` より手前の行は **NaN** で埋める。0 埋めにすると `t0` の取り違えが
「少しずれた学習結果」として静かに通ってしまうため、`fit_ridge` 側で非有限値を
`ValueError` にして大きな音で落とす（D-05 の防衛線の補強）。

### 6.4 リッジ回帰と alpha 選択

閉形式 `inv(ΦᵀΦ + α·D) ΦᵀY` を `scipy.linalg.solve(..., assume_a="pos")` で解く。
罰則行列は `D = diag(0, 1, 1, …)` で、**バイアス列を正則化しない**（D-03）。
バイアスを縮めると予測の平均が目標の平均からずれ、「NRMSE = 1 が平均予測と同等」
という基準線（D-02）の意味が壊れる。`bias=False` の設計行列では先頭の実特徴が
誤って無罰則にならないよう、`bias_column_index()` が `None` を返して全列を罰する。

alpha は検証 NRMSE が最小のものを選び、同点なら**大きい方**（保守側）を取る。
探索格子は関数側に既定値を持たせず、呼び出し側が `config.ridge.alpha_grid` を渡す。
格子の既定値が2か所に存在すると「全手法が同一格子を読む」（D-04）が静かに破れるため。

実際に使う格子の範囲と、その端が選ばれることの意味は §8 に分けて書いた。

### 7.1 実験1-A: 3手法の比較（テスト区間・5レプリケート）

NRMSE 平均 ± 標準偏差（標準偏差は ddof=1）:

| 課題 | 線形 | 遅延線 | ESN |
|---|---|---|---|
| Mackey-Glass (1ステップ先) | 0.1454 ± 0.0002 | **0.0005 ± 0.0000** | 0.0007 ± 0.0001 |
| 遅延パリティ | 1.0004 ± 0.0003 | 1.0007 ± 0.0007 | **0.0894 ± 0.0166** |

符号正解率（遅延パリティ）: 線形 0.500 / 遅延線 0.522 / **ESN 1.000**。
選ばれた `n_lags`: MG では 5/5 回とも格子上限の 64、遅延パリティでは 1 / 2 / 8 が
ばらつく（後者はどの `n_lags` でも解けないため、検証 NRMSE の差がノイズになっている）。
MG で上限が選ばれ続けるのは探索の失敗ではなく、`n_lags` の効きが k=64 で
プラトーに達しているため（§8.2 に k=128 までの実測を置いた）。
選ばれた alpha も MG ではほぼ全て格子下端 1e-10 で、これも同様に期待される挙動
（§8.1・D-11）。

読み取り:

- **遅延パリティは §2.2 の解析どおりに割れた**。線形・遅延線は NRMSE ≈ 1.0
  （= 平均予測と同等、D-02）かつ符号正解率 ≈ 0.5（= コイン投げ）で、
  ±1σ 区間は ESN と重ならない。仕様 §3 の受け入れライン
  （線形系 NRMSE ≥ 0.95 かつ符号正解率 ≤ 0.60、ESN NRMSE ≤ 0.50 かつ
  符号正解率 ≥ 0.90）を満たす
- **Mackey-Glass では遅延線が ESN を上回る**（0.0005 対 0.0007）。
  これは隠さずそのまま書く。Δt=1.0 の MG は1ステップ先ならほぼ線形予測可能で、
  64 ラグの遅延線に十分な情報がある。**MG だけを見れば遅延線で足りる**のであり、
  差が出るのは非線形性を要求する遅延パリティの側である、というのが本連載の筋
- 探索予算は遅延線（alpha × `n_lags`）の方が ESN（alpha のみ）より大きい。
  非対称性は ESN に不利な側へ倒してある（D-08）。上の MG の結果はその条件下のもの

### 7.2 実験1-B: 入力空間とリザバー状態空間の PCA

分割窓（7800 行）で 3 つの空間の PCA を取った実測値（`meta.json` の `state_space`）:

遅延埋め込みのラグ数は `max(ridge.n_lags_grid)`（= 遅延線ベースラインが実際に使う
最大の特徴空間）なので、格子拡張に伴い 16 ラグ → **64 ラグ**（65 次元）になっている。

| 課題 | 空間 | 次元 | `n_components_95` | participation ratio |
|---|---|---|---|---|
| Mackey-Glass | 生の入力 | 1 | 1 | 1.00 |
| Mackey-Glass | 入力の遅延埋め込み (64ラグ) | 65 | 5 | 2.73 |
| Mackey-Glass | リザバー状態 | 200 | 2 | 1.39 |
| 遅延パリティ | 生の入力 | 1 | 1 | 1.00 |
| 遅延パリティ | 入力の遅延埋め込み (64ラグ) | 65 | **62** | 64.33 |
| 遅延パリティ | リザバー状態 | 200 | **4** | 2.11 |

**受け入れ条件4 の扱い（重要・正直な結果）**:

- 「生の入力（1次元）より状態空間が高次元」は両課題で成立する（1 → 2 / 1 → 4）。
  これを `tests/test_state_space.py::test_reservoir_state_spans_more_components_than_the_raw_input`
  で固定した
- **「遅延埋め込みした入力より高次元」は成立しない**。MG では状態 2 に対し
  遅延埋め込み 5、遅延パリティでは状態 4 に対し遅延埋め込み 62 で、
  いずれも**状態空間の方が低い**（格子拡張前も同じ向きで、差が広がっただけ）
- 理由ははっきりしている。遅延パリティの入力は ±1 の i.i.d. なので、遅延埋め込みは
  65 方向が等分散の等方空間になり（participation ratio 64.33 ≈ 65）、
  分散基準の次元数は自動的に 62 まで上がる。
  一方リザバーは入力を低次元の滑らかな軌道へ**圧縮**し、パリティを解く交差項
  `u[t-1]u[t-2]` は**分散の小さい裾の主成分**に載る。分散で数える次元は
  「線形読み出しが使える特徴の豊かさ」とは別物である
- したがって記事01 では「PCA の主成分数が増える」ではなく、
  **`fig_state_space.png` 下段左の散布図（リザバー状態が直近ビットのパターンごとに
  8 個の塊へ分離している）**を示し、「線形分離できる形へ配置し直される」という
  読み方をする。同じ図の中段（遅延埋め込みは等方な雲のまま）が対照になる
- 分散基準の次元数（`n_components_95` / participation ratio）だけでリザバーの効用は
  測れない、というのはサイクル03（IPC）で正面から扱う論点であり、
  ここでは実測値を残すに留める

## 8. 探索格子（拡張の経緯と、その後に分かったこと）

初版の格子は `alpha_grid` の下端 1e-8、`n_lags_grid` の上端 16 だった。実測すると
Mackey-Glass では **alpha が 14/15 回で下端 1e-8、遅延線の `n_lags` が 5/5 回で
上端 16** を選んでおり、「格子の端が選ばれている＝探索が収束していない」という
一般則に照らして格子を広げた（下端 1e-10 / 上端 64。ユーザー承認のうえ再実行済み）。

拡張後に検証曲線そのものを実測した結果、**この動機は半分が誤りだった**。
以下はその記録である。数値は再実行後の実測値（レプリケート0・検証分割）。

### 8.1 alpha には内点解が存在しない（欠陥ではなく事実・D-11）

Mackey-Glass の検証 NRMSE は alpha に対して**単調増加**で、最適は alpha → 0
（すなわち OLS）にある。遅延線 k=64 の実測:

| alpha | 1e-10 | 1e-9 | 1e-8 | 1e-7 | … | 100 |
|---|---|---|---|---|---|---|
| 検証 NRMSE | 5.292627e-04 | 5.946133e-04 | 7.258906e-04 | 9.625484e-04 | （単調） | 2.467684e-01 |

ESN（N=200）も同形（1e-10 → 8.171786e-04 … 100 → 2.044276e-01）。
つまり **MG で格子下端が選ばれ続けるのは探索の失敗ではなく、期待される挙動**である。
「格子端が選ばれている＝探索予算が足りない」という一般則をこの実験に機械的に当てはめると
誤診になる。これを `.claude/decisions.yaml` の **D-11** として記録し、guard_test
`tests/test_alpha_grid_lower_bound.py::test_mackey_glass_validation_nrmse_is_monotone_in_alpha`
（縮小設定で単調性と「下端が最良」を固定）に紐づけた。内点解が現れた瞬間に落ちる。

**下端 1e-10 は数値限界であって、恣意的な打ち切りではない**。実測で
`cond(Phi^T Phi)` は遅延線 k=64 で **2.0e16**、ESN N=200 で **8.0e18** に達しており、
無正則化の Gram 行列は倍精度では既に数値的に特異（`1/eps ≈ 4.5e15` 超）である。
alpha が正定値性を供給している状態であり、`alpha <= 1e-11` では `fit_ridge` の
`scipy.linalg.solve(assume_a="pos")` が `LinAlgError: A singular matrix detected` で
落ちる（実測）。したがって下端 1e-10 は**実行可能領域の境界**であり、
「下端が選ばれたから、さらに下へ延ばす」という手は取れない。

`LinAlgError` になること自体はテストにしていない。失敗の出方（例外の種類・発生する
alpha の境目）が BLAS/LAPACK 実装に依存し、環境差で偽陽性を生むため。代わりに
`test_alpha_grid_lower_bound_is_a_numerical_limit` で、(1) 無正則化の Gram が
`cond > 1/eps` で数値的に特異、(2) 格子下端では実際に解ける、の2点を測っている。

### 8.2 `n_lags` は k=64 でプラトーに達した

こちらは初版の見立てが当たっていた。alpha を各点で最良化した MG の検証 NRMSE:

| `n_lags` | 16 | 32 | 64 | 96 | 128 |
|---|---|---|---|---|---|
| 検証 NRMSE | 5.875641e-04 | 5.607482e-04 | 5.292627e-04 | 5.091023e-04 | 5.072052e-04 |

初版の上限 16 は k=64 比で約 10% 悪く、**遅延線を過少評価していた**（`n_lags` は
遅延線だけが持つ軸なので、上端張り付きは対照に対して非対称に不利に働く。D-08 で
「非対称性は ESN に不利な側へ倒す」と宣言している以上、これは直すべき欠陥だった）。
一方 k=64 以降は頭打ちで、96 → 128 の改善は **0.4%** しかない。
**MG で上限 64 が選ばれ続けるのは、格子が足りないからではなく効きが飽和しているため**
であり、これ以上の拡張は探索予算の非対称性を広げるだけで結論を変えない。

### 8.3 拡張の前後で変わったもの・変わらなかったもの

- 変わった: MG の遅延線 0.0008 → **0.0005**、MG の ESN 0.0014 → **0.0007**
  （どちらも alpha 下端の拡張ぶんが効いている。ESN は `n_lags` を持たない）
- 変わった: §7.2 の遅延埋め込み空間が 16 ラグ（17 次元）→ 64 ラグ（65 次元）
  （PCA の埋め込みラグ数は `max(ridge.n_lags_grid)` に配線されているため）
- **変わらなかった: 結論の向き**。MG は依然として遅延線 < ESN（遅延線の方が良い）、
  遅延パリティは linear/delay_line ≈ 1.0 に対し ESN 0.0894 のまま。
  「MG の1ステップ先予測だけ見れば遅延線で足りる。差が出るのは非線形性を要求する
  パリティ」という連載の筋は、格子を両側に広げても変わらない

## 9. ESP 判定の既定値とその根拠

### 9.1 距離・閾値・窓（D-16）

ESP は「同じ入力を受ける2つの軌道が、初期状態の違いを忘れるか」なので、
測るのは **2軌道間の距離**である。定義は

```
d_i[t] = || X[t] - C_i[t] || / sqrt(N)        (RMS/ユニット距離)
converged = ( d_tail <= max(abs_tol, rel_tol * d_initial) )
d_tail    = max_i  median( d_i[末尾 window ステップ] )
d_initial = min_i  d_i[0]
```

| 項目 | 既定値 | コード上の出どころ |
|---|---|---|
| 絶対閾値 `abs_tol` | `1.0e-6` | `diagnostics.esp.DEFAULT_ESP.abs_tol` |
| 相対閾値 `rel_tol` | `1.0e-3` | `diagnostics.esp.DEFAULT_ESP.rel_tol` |
| 判定窓 `window` [ステップ] | `200` | `diagnostics.esp.DEFAULT_ESP.window` |
| 減衰率の当てはめ開始オフセット `fit_skip`（診断の既定） | `50` | `diagnostics.esp.DEFAULT_ESP.fit_skip` |
| 同上（02 の実験が使う値・D-22） | `10` | `config.Esp02Config.esp.fit_skip` |
| 対数を取る前の距離の床 `floor` | `1.0e-14` | `diagnostics.esp.DEFAULT_ESP.floor` |
| ESP 距離に使う washout（D-22） | `0` | `experiment.esp.ESP_DISTANCE_WASHOUT` |
| 比較軌道の本数 `n_pairs`（D-21） | `10` | `config.DriveConfig.n_pairs` |
| 系列長 `n_steps` [ステップ] | `3000` | `config.DriveConfig.n_steps` |
| λ・自己相関の washout | `200` | `config.DriveConfig.washout` |

**なぜ `sqrt(N)` で割るか。** 閾値をユニット数に依存させないため。素の L2 ノルムだと
同じ「1ユニットあたりの食い違い」でも N が4倍になれば距離は2倍になり、N の違う系
（メモリスタ配列など）へ移植した瞬間に閾値の意味が変わる。

**なぜ `abs_tol = 1e-6` か。** float64 の eps（2.2e-16）から10桁上にあり、
初期距離 O(1) から **6桁の収縮**を要求する。丸め誤差と紛れず、かつ図の描画分解能
（線の太さ）よりはるかに厳しい。実測では収束する条件の `d_tail` は 1e-16 台、
収束しない条件は 0.1〜1 台にはっきり割れており、その**間に4桁以上の空白がある**
（下の 9.2 が示すのはまさにこの空白の広さである）。

**なぜ `window = 200` か。** 判定を最終ステップ1点にすると、たまたま2軌道が
近づいた瞬間を拾う。窓の**中央値**を取れば一過性の接近では動かない。値は 01 の
washout（200）と同じ桁に合わせた（`n_steps = 3000` の 6.7%）。

**なぜ最悪値（`d_tail` は最大・`d_initial` は最小）か。** ペアごとに判定して AND を
取ると、CSV に載る `d_initial` / `d_tail` / `converged` の3列が別々のペア由来になり、
**行を見ても判定を再現できなくなる**。最悪値方式は AND より厳しい側（安全側）に倒れる。

### 9.2 閾値感度 —— 既定値は結論を作っていない（要件_02 設計判断3）

既定値は判定基準そのものなので、値を動かすと結論が変わるなら、記事は現象ではなく
閾値の選び方を語っていることになる。`abs_tol` 3点 × `window` 3点の**9通り**で
2-C の格子（16ρ × 7σ × 3レプリケート = 336 条件）を判定し直し、
**σ 別の臨界 ρ**（= ρ 昇順で収束率が過半数を割る最初の ρ）がどれだけ動くかを測った。

一次資料は `results/02_esp_and_dynamics/esp_threshold_sensitivity.csv`（9行）。
再生成は `make threshold-02`。下表と CSV の**行数・値の一致**は
`tests/test_design_doc.py` が検査する。

| `abs_tol` | `window` | σ=0 | σ=0.05 | σ=0.1 | σ=0.2 | σ=0.5 | σ=1.0 | σ=2.0 | `n_converged` |
|---|---|---|---|---|---|---|---|---|---|
| 1.0e-4 | 100 | 1.0 | 1.1 | 1.1 | 1.3 | 1.5 | 1.7 | — | 208 |
| 1.0e-4 | 200 | 1.0 | 1.1 | 1.1 | 1.3 | 1.5 | 1.7 | — | 208 |
| 1.0e-4 | 400 | 1.0 | 1.1 | 1.1 | 1.3 | 1.5 | 1.7 | — | 207 |
| 1.0e-6 | 100 | 1.0 | 1.1 | 1.1 | 1.3 | 1.5 | 1.7 | — | 208 |
| 1.0e-6 | 200 | 1.0 | 1.1 | 1.1 | 1.3 | 1.5 | 1.7 | — | 208 |
| 1.0e-6 | 400 | 1.0 | 1.1 | 1.1 | 1.3 | 1.5 | 1.7 | — | 207 |
| 1.0e-8 | 100 | 1.0 | 1.1 | 1.1 | 1.3 | 1.5 | 1.7 | — | 208 |
| 1.0e-8 | 200 | 1.0 | 1.1 | 1.1 | 1.3 | 1.5 | 1.7 | — | 208 |
| 1.0e-8 | 400 | 1.0 | 1.1 | 1.1 | 1.3 | 1.5 | 1.7 | — | 207 |

「—」は**格子内に境界が無い**こと（σ=2.0 では ρ=1.9 まで全点で ESP が成立する）。
格子上端 1.9 と区別するため CSV では `nan` にしてある。

読み取り:

- **臨界 ρ は9通りで1点も動かない**（`n_sigma_shifted = 0` が9行すべて）。
  `abs_tol` を4桁（1e-4 〜 1e-8）動かしても判定が変わらないのは、9.1 で述べた
  「収束する側 1e-16 / しない側 0.1〜1」の空白が4桁以上あるためである
- 336 条件のうち判定が動いたのは **`window = 400` の 1 件だけ**（208 → 207）。
  窓を系列長の 13% まで広げると過渡を含み始めるが、それでも臨界 ρ は動かない
- したがって **2-C の主張（入力を強くすると ESP が成立する ρ の上限が上がる）は
  閾値の選び方に依存しない**。記事にはこの表を「閾値をどう選んでも結論が同じ」
  という形で添える

臨界 ρ そのものが 2-C の結論である:

| σ_u | 0 | 0.05 | 0.1 | 0.2 | 0.5 | 1.0 | 2.0 |
|---|---|---|---|---|---|---|---|
| ESP が壊れる最小の ρ | 1.0 | 1.1 | 1.1 | 1.3 | 1.5 | 1.7 | 格子外 (>1.9) |

無入力では通説どおり ρ=1.0 が境界だが、σ_u を上げると境界は単調に上がり、
σ_u=2.0 では ρ=1.9 でも ESP が成立する。これが Scholarpedia（Jaeger 本人）の
「ESP を ρ<1 と同一視するのは広く流布した誤り」の再実演である。

### 9.3 条件付き Lyapunov 指数 —— 摂動サイズと再正規化間隔（D-18）

| 項目 | 既定値 | コード上の出どころ |
|---|---|---|
| 推定法 `method` | `'perturbation'` | `diagnostics.esp.DEFAULT_LYAPUNOV.method` |
| 摂動サイズ `delta`（RMS/ユニット） | `1.0e-8` | `diagnostics.esp.DEFAULT_LYAPUNOV.delta` |
| 再正規化間隔 `renorm_interval` [ステップ] | `1` | `diagnostics.esp.DEFAULT_LYAPUNOV.renorm_interval` |
| 暴走検出の上限 `max_growth` | `1000.0` | `diagnostics.esp.DEFAULT_LYAPUNOV.max_growth` |
| 伝播器の整合検査 `check_propagator` | `True` | `diagnostics.esp.DEFAULT_LYAPUNOV.check_propagator` |
| 同上の許容距離 `propagator_tol` | `1.0e-10` | `diagnostics.esp.DEFAULT_LYAPUNOV.propagator_tol` |
| 自己相関の最大ラグ `max_lag` | `200` | `diagnostics.timescale.DEFAULT_TIMESCALE.max_lag` |

**なぜ `delta = 1e-8` か。** 摂動法の誤差は2つの逆向きの成分からなる。
摂動を大きくすると非線形項（`O(delta²)`）が効き、小さくすると差の丸め誤差
（`O(eps / delta)`）が効く。両者が釣り合うのが `delta ≈ sqrt(eps) = 1.49e-8` であり、
数値微分の古典的な最適点である。`delta` は距離の定義（D-16）と土俵をそろえて
**RMS/ユニットで解釈**する（摂動ベクトルの L2 ノルムは `delta * sqrt(N)`）。
実効性は解析解との照合で確認済み —— 線形写像 `x -> A x` に対する
`lyapunov_per_step` の `log ρ` からの相対誤差は
**ρ=0.5 で 5.0e-10 / ρ=0.9 で 8.8e-12 / ρ=1.1 で 2.2e-9**。

**なぜ再正規化間隔 1 ステップか。** 間隔を伸ばすほど摂動は線形域から出る。
間隔1なら「1ステップぶんの局所拡大率の対数の平均」がそのまま定義になり、
解析解と直接照合できる（上の 1e-9 台の一致がその証拠）。コストは軌道を
もう1本ぶん回すだけで、本番でも問題にならない（2-C 336 条件で 76 秒）。

**線形域の内側にいることの実測**: 本番 2-C 格子 336 条件で、1区間あたりの成長率
`max_observed_growth` は**最大 1.5372 / 中央値 1.0873**（最大は ρ=1.9・σ_u=0.2）。
1ステップで1桁も成長しておらず、`max_growth = 1000` に対して **650 倍の余裕**がある。
`max_growth` は推定の一部ではなく「前提が崩れたときに黙って値を返さない」ための
暴走検出であり、両者が接近していたら再正規化間隔が長すぎるというサインになる。
余裕そのものを `test_perturbation_growth_stays_far_below_the_runaway_limit` で固定した。

**なぜ伝播器の整合を実行時に検査するか。** `X[t]` は `u[t]` を処理した**後**の状態
なので、1ステップ進める伝播器は `propagator(x, t) = esn.step(x, u[t+1])` である。
`u[t]` を渡す配線ミスは λ を「それらしい値」で返すためレビューでは見つからない。
実測: `u[t]` に差し替えると `check_propagator` が全条件で `ValueError` を出し、
検査を切ると λ が **-0.02 から +15〜+17** へ跳ねる。この検査は既定で有効のままにする。

### 9.4 入力強度の定義と初期状態の生成（D-17 / D-21）

**入力強度は駆動信号の標準偏差 σ_u で定義する**（振幅ではない）。i.i.d. 一様分布
`U[-a, a]` では `a = sqrt(3) σ_u` なので、指定量を振幅と取り違えると実際の強度が
**0.577 倍**ずれ、2-C の境界位置がそのぶん動く。CSV には `sigma_u`（指定値）/
`input_amplitude`（`sqrt(3) σ_u`）/ `input_drive_std`（生成した系列の実測標準偏差）の
3列を並べ、取り違えが列の食い違いとして表に出るようにした。掃引中 `input_scale` は
1.0 に固定する（信号と重みを同時に動かすと、どちらが効いたのか分離できない）。

**初期状態**は `U[-1, 1]^N` から `n_pairs + 1` 本を**独立に**引く（参照軌道1本 +
比較軌道 `n_pairs` 本）。乱数は4本目のストリーム `SeedStream.PROBE` から取り、
リザバー重み（`RESERVOIR`）や駆動信号（`TASK`）と独立に振れるようにしてある（D-14）。
**片方をゼロ状態にしない**: 無入力ではゼロが不動点なので、片方を 0 にすると
「2軌道の分離」ではなく「単一軌道の原点への収束」を測ることになり、ESP と別の量に化ける。

**なぜ `n_pairs = 10` か。** 無入力・ρ>1 の tanh リザバーは `+x*` / `-x*` の対をなす
吸引子を持つことがあり（9.5）、比較軌道が k 本すべて参照軌道と**同じ側**へ落ちる確率が
約 `2^-k` 残る。この事故は「ESP が成立した」という**偽陽性**として出る。
仕様の初期値 `n_pairs = 3` は偽陽性確率が `2^-3 = 1/8` あり、実測でも特定の
リザバー draw（replicate 2）で ρ=1.05〜1.5・無入力が「収束」と誤判定され、
受け入れ条件1 が全レプリケートでは成立しなかった。10 本（`2^-10 < 0.1%`）にすると
全レプリケートで正しく非収束になり、ρ<1 側の判定は変わらない
（`n_pairs = 30` まで上げても偽陰性は出ない）。代償は本番 wall time 43.2 → 83.3 秒。

**なぜ `bias_scale = 0` か。** `ESNConfig` の既定は 0.1 だが、定数バイアスは
`[1; u]` の先頭成分に掛かる**振幅一定の入力そのもの**である。D-17 が入力強度を
駆動信号の標準偏差で定義している以上、その定義に入らない常時入力を残したままでは
`σ_u = 0` を「無入力」と呼べない。実測: `bias_scale = 0.1` では無入力・ρ=1.2 でも
2軌道が収束し、受け入れ条件1（「無入力で ρ>1 なら非収束」）が成立しない。

### 9.5 λ の符号と ESP 判定の不一致 —— 多安定性という実在の現象（D-20）

局所量（λ）と大域量（2軌道の合流）は一致するはずだが、本番格子では一致しなかった。
実測（`meta.json` の `verdict_lyapunov_agreement`。369 行のうち境界帯 `|λ| <= 0.01` の
37 件を除く 332 件が比較対象）:

| 向き | 件数 |
|---|---|
| λ>0 なのに収束（**偽の ESP**） | **0** |
| λ<0 なのに非収束（局所安定だが大域では合流しない） | **27**（8.13%） |
| うち強駆動 σ_u ≥ 0.5（158 件中） | **0** |

不一致の内訳:

- σ_u 別: 0.0 が 8 件 / 0.05 が 7 件 / 0.1 が 8 件 / 0.2 が 4 件。**σ_u ≥ 0.5 は 0 件**
- ρ 別: 1.1 が 6 件 / 1.2 が 6 件 / 1.3 が 4 件 / 1.4 が 4 件 / 1.5 が 5 件 / 1.6 が 2 件。
  **ρ ≤ 1.0 は 0 件**

つまり不一致は**弱駆動かつ臨界超え**の一角に完全に限局し、向きも一方向だけである。
仕様 §7 のリスク2 は「境界近傍以外で 5% を超えたら実装誤りを疑え（最有力は伝播器の
入力インデックスずれ）」としていたが、**実装誤りではなかった**。

**先に否定したもの**: 伝播器のインデックスずれは `check_propagator` が全 336 条件で
通過している（9.3 の実測）。

**原因は多安定性である。** tanh は奇関数なので、`x*` が無入力時の不動点なら `-x*` も
不動点になる。**各不動点は局所安定（λ<0）でありながら、初期状態によって行き先が割れる**
（= ESP 不成立）。条件付き Lyapunov 指数は参照軌道まわりの**局所**量なので、
この状況を原理的に検出できない。ρ=1.1・σ_u=0・replicate 0 で4軌道を直接観測した実測:

| 量 | 実測値 |
|---|---|
| 各軌道の末尾200ステップの時間 s.d.（RMS/ユニット） | 6.4e-16（4本とも = 全軌道が不動点に到達） |
| `d(traj0, traj1)` | 1.2e-16 |
| `d(traj0, traj3)` | 1.6e-16 |
| `d(traj0, traj2)` | **5.3e-01** |
| `‖x0* + x2*‖ / sqrt(N)` | 1.3e-16（= `x2*` はちょうど `-x0*`） |
| この条件の `lyapunov_per_step` | **-0.032**（局所安定） / `converged = 0` |

4本中3本が同じ不動点へ、1本が**符号を反転した対の不動点**へ落ちている。
最後の行が「奇対称な対の吸引子」という説明を直接裏づけている。

したがって整合の要求は**非対称**にした（D-20）:

- 「λ>0 なのに収束」（偽の ESP）は理論上あり得ないので **0 件を厳格に要求**する。
  伝播器のずれや閾値の緩みはこちら側で落ちる
- 「λ<0 なのに非収束」は**許容**し、件数と σ_u / ρ の内訳を `meta.json` に残す
- 両者の完全一致は**駆動が十分ある領域（σ_u ≥ 0.5）でのみ**要求する

**この非対称性を「揃っていないから」と対称化してはいけない。** 対称化すると、
実在の現象を実装バグとして潰すことになる。次に同じ比率を見たときの確認順序は
(1) 一方向（λ<0 側）に偏っているか (2) σ_u ≤ 0.2 かつ ρ > 1 に限局しているか。
偏っていれば多安定性、偏っていなければ実装を疑う。**偽の ESP が1件でもあれば実装誤り**である。

### 9.6 実験 2-D: washout 感度 —— タスク選定と `pad_series`（D-19）

**タスク選定**: 01 の2課題（Mackey-Glass と遅延パリティ）を**両方**使い、3手法
（線形 / 遅延線 / ESN）すべてを回す。実体は `dataclasses.replace` で `washout` だけを
差し替えて既存の `run_experiment` を呼ぶループなので、公平性（D-04 / D-05 / D-08）は
既存経路がそのまま担保する。図の主役は MG × ESN に固定した
（`HEADLINE_TASK` / `HEADLINE_METHOD`。掃引に主役の組が無ければ `ValueError`)。

**当初の予測**: 「MG はリザバー状態の過渡が効くので washout に反応し、遅延パリティは
i.i.d. 入力なので反応しない対照になる」。この予測は**支持されなかった**（下記）。

**なぜ `pad_series` が要るか（交絡の除去）**。`make_split` は
`n_usable = T - max_start_offset - t0` で行数を決めるため、washout を増やすと
**訓練データ量が同時に減る**。素直に掃引すると「washout の効果」と「訓練データ量の
効果」が交絡し、受け入れ条件5 が別の量の測定になる。しかもこの交絡は
**滑らかな単調曲線**として出るので、図を見ても気づけない。

補償量は washout の差分ではなく **`t0` の差分**である:

```
length = base_length + ( t0(washout) - t0(min(grid)) )
```

仕様草案の `base_length + (max(grid) - washout)` は**符号が逆**で、そろえるどころか
差を広げる（変異注入すると行数が 348/310/230/110 に割れる）。また
`t0 = max(washout, 各手法の first_valid)` は**飽和する**ため、washout の差分では
そろわない —— 本番格子では遅延線の最大ラグ 64 により washout=0 と 50 がどちらも
`t0 = 64` になり、washout 差分の補償では washout=0 だけ行数がずれる（228 対 230）。
`t0` は系列を作る**前に**知る必要があるので、`readout.design.first_valid_for(spec)` を
追加して予測経路と実経路が同じ値を返すことを構造で保証した。

**実測（本番格子 / `pad_series = True`）**:

| washout | 0 | 50 | 100 | 200 | 400 | 800 |
|---|---|---|---|---|---|---|
| `t0` | 64 | 64 | 100 | 200 | 400 | 800 |

より短い系列で測ることはない）。

**受け入れ条件5 の結論（重要・否定的結果）**:

- MG × ESN の NRMSE の (最大/最小) 比は **1.00763**

## 11. 容量測定（MC / IPC）の設計（サイクル03 3a）

### 11.1 容量測定の定義と正規化

MC（線形メモリ容量）と IPC（情報処理容量）はどちらも「状態 `X` に対して、
目標 `z_k` を線形読み出しでどれだけ説明できるか」を測る同一の量であり、
違いは目標の作り方だけである（Dambre 2012）。容量は決定係数

```
C_k = 1 - ||z_k - Phi w_k||^2 / ||z_k||^2        (w_k はリッジ回帰の閉形式解)
```

で、目標が入力測度に対して正規直交である限り `Σ C_k <= N`（保存則、N は状態の
次元）。この節は両診断が共有する回帰カーネル（`diagnostics._capacity`）の設計を記す。

**t0（単一基準点、D-24）。** 遅延 `k` の目標は先頭 `k` 行が未定義になる。素直に実装すると
遅延が深いほど使える標本数が減り、容量が系統的に下がる —— これは測りたい現象
（記憶の減衰）と**まったく同じ向き**に出るため、プロファイルの図を見ても気づけない。
そこで `t0 = max(ctx.washout, 全目標の最大遅延)` を単一の基準点にし、全目標が
同一の行集合 `X[t0:]` を共有する。

**行合わせの担い手は `RowAlignment` 1つである（04a T3 で D-24 を改訂）。**
`t0` と `n_samples` **だけ**を持つ値で、(i) 基準点の算出 `RowAlignment.from_series(
n_steps=..., washout=..., max_delay=...)`、(ii) `t0 >= T` の拒否、(iii) 遅延窓の
切り出し `RowAlignment.lagged(series, delay)`（`series[t0 - delay : t0 - delay +
n_samples]`）の3つをここ1箇所に置く。round 1（F-03-1-001）で統合したのは (iii) だけ
で、(i)(ii) は `memory_capacity` と `ipc` に2箇所複製されたまま残っていた。
`CapacityProblem` は `RowAlignment` を内包し、構築時に「状態から切り出した行数」と
`rows.n_samples` の一致を検査する。

`RowAlignment` が**状態行列にも Gram にも触れない**ことがこの型の存在理由である。
行合わせだけを検査するテストは、以前は値を使わないダミーの状態行列（と、その特異な
Gram）を構築していた。いまは `RowAlignment(t0=42, n_samples=458)` を直接作れば足りる
（`test_row_alignment_needs_no_state_matrix`）。

**Gram 共有カーネル（D-26）とブロック分解（round 1 で追加）。** 回帰の左辺
`Phi = [1, X]` の Gram `Phi.T @ Phi` は条件ごとに1回だけ作り、目標が何本増えても
作り直さない。容量は Gram 量だけで閉じる形

```
||z - Phi w||^2 = z.T z - 2 w.T (Phi.T z) + w.T (Phi.T Phi) w
```

で評価するため、目標数 K を増やしても `O(T F K)` の走査は `rhs = Phi.T @ Z` の
1回で済む。当初の実装は `Phi` を `np.concatenate((ones, X))` で実体化しており、
T=1e6 級の本番設定で `X` と同じ大きさのコピーがもう1枚でき、単独でメモリ予算
4GB の9割近くを消費する BLOCKER だった（F-03-1-013）。バイアス列は定数列なので
Gram は `[[T_eff, sum(X,0)], [sum(X,0).T, X.T @ X]]` にブロック分解でき、`Phi`
そのものは一度も作らずに済む。`CapacityProblem` はこのブロック Gram と、`X` の
ビュー（コピーなし）だけを保持する。

**D-25 の固定 alpha。** 容量は「線形読み出しで到達可能な最大の説明率」という
定義そのものなので、検証分割による alpha 選択（D-04）は行わない。alpha=0 は
数値的に不安定（`Phi.T Phi` の条件数が `~1e18` に達しうる、D-11 の実測と同型）
なので、数値安定の下駄として微小な固定値を使う。

**D-28 の正規直交化。** 目標を作る多項式基底（Legendre / Hermite）は、宣言された
入力分布に対して正規直交でなければならない。直交していない基底で目標を作ると
容量が目標間で二重計上され、保存則が「N をわずかに超える」という穏やかな形で
破れる（図では気づけない）。対応する組は `(uniform, legendre)` と
`(normal, hermite)` の2つのみで、未対応な組は黙って Legendre に倒さず
`ValueError` にする。正規化は入力の**実測**の平均・標準偏差で行う（振幅に
追従させるため、D-17 と両立する）。

**この2つは対でのみ意味を持つので、04a T3 で `InputMeasure`（frozen / slots、
`distribution` と `basis`）1値にまとめた。** `orthonormal_basis(u_lagged, degree,
measure)` の第3引数は**既定値を持たない** —— これが D-28 の改訂の実体で、
「片方だけ渡す」呼び方（改訂前は `distribution` に既定値 `uniform`、`basis` に
既定値 `legendre` があった、F-03-1-006）を型検査の時点で書けなくする。未対応の組は
`InputMeasure` の**構築時点**で `ValueError` になり、検査は1箇所しかない。
設定層（`IpcConfig`）は YAML と `meta.json` の面を変えないため `basis` /
`input_distribution` の**2つの文字列フィールドのまま**保ち、`ipc()` が入口で
1度だけ畳む（設定 dataclass を1値へ置き換える案は、`results/` のバイト不変という
04a T3 の唯一の証明手段を壊すため却下した。ADR 0002 §9-1）。

**チャンク幅は性能軸と確保軸に分ける（D-33、04a T3 で改訂）。** 改訂前は1つの
実効値（`CapacityProblem.effective_chunk_size`）が3つの用途 —— (A) 実目標の solve 幅、

(C) には性能上の意味が一切無く、**運用者の性能ノブ `cfg.chunk_size` が確保上限を

| 軸 | メソッド | `cfg.chunk_size` を読むか | 何を決めるか |
|---|---|---|---|
| 性能軸 | `RowAlignment.solve_width(configured)` | **読む**（上限として） | 1回の solve に畳む目標の列数 (A)(B) |
| 確保軸 | `RowAlignment.block_width(n_columns)` | **読まない** | 一度に実体化してよい列数 (C) |

持たない）。`params` に記録する `chunk_size_effective` は引き続き性能軸 (A) の値で、
確保軸の実効値は記録しない。本番の値は変わらない（`min(4, 83) = 4` は改訂前の
1ブロック4列と同一。全条件で `n_surrogate_targets` = 4 <= 予算列数 16〜847 を実測）。

chunk_size`）が `_MAX_CHUNK_BYTES`（128 MiB）を超える場合に限り、実装が
`RowAlignment.solve_width` 経由で `configured` より小さい実効値へ
下げる（`configured` より大きくはしない）。この判断と根拠は round 1 の
BLOCKER 修正（F-03-1-012/013）の副産物として `bounded_chunk_size` に実装
されていたが、round 1 では正本（decisions.yaml / design.md / plan doc）の
どこにも記録されていなかった（F-03-2-002）。成果物の `params` には設定値

round 3 でこの決定を D-29 から D-33 へ改番した（F-03-3-001）:
`docs/plans/rc-basics-03.md` line 9（ユーザー承認済み）が 3b 用に

**IPC の確保・組合せ計算量を縛る3段の上限（D-34、round 3 で追加）。**
`max_degrees`（既定20）は `len(max_delay_by_degree)` の上限で、`psi_table`
（次数の本数 x 系列長）の確保サイズを縛る。`max_degrees` 自身にも上書き
不能な絶対上限 `_MAX_DEGREES=32` を置く（`max_degrees` を引き上げるだけで
上記の検査を素通りできないようにするため、F-03-3-019）。`max_variables`
には上書き不能な絶対上限 `_MAX_VARIABLES_FOR_COUNT=20` を置き、
`count_targets` の閉形式（`math.comb`）の組合せ爆発を縛る。3つとも
`_validate_config`（延いては `count_targets` の先頭、F-03-3-018）で
確保・列挙より前に検査する。

**`max_targets` は「目標数の上限」ではなく共有予算の終端である（04a T3 で
D-34 の rule を改訂）。** 4段の絶対上限の外に、運用者が宣言する予算 `max_targets`
が1本あり、これは**単位の違う複数の確保軸を1本で縛っている**。縛っている軸の
列挙が正本で、`diagnostics.ipc.MAX_TARGETS_BOUNDED_AXES` に置く。

| 軸 | 単位 | 本番の値（最深設定） | `max_targets`（200,000）に対する余裕 |
|---|---|---|---|
| `target_count`（目標数） | 本 | 4,075 | **49 倍** |
| `heatmap_cells`（`ipc_heatmap` のセル数） | セル | 800 | **250 倍** |

軸ごとに別の設定フィールドへ分けることは**行わない** —— 機能的な必要が無く
（上表の余裕）、運用者が正しく設定すべきノブを1本増やすだけになる（`IpcConfig` に
新フィールドを足すと `meta.json` に新キーが出て `results/` のバイト不変も崩れる。
実測で確認済み）。**どちらかの余裕が10倍を切ったら分離を再検討する。**
軸を足すときは列挙表とパラメトライズしたテストの両方に足す
（`test_max_targets_bounded_axes_are_enumerated` が完全性を検査する）。round 2 でこの判断の根拠がコードコメントにしか
無く、`design.md` も存在しない決定（D-29）を誤って参照していた
（F-03-3-003）。

**「引き上げ可能な実験パラメータ」と「引き上げ不可の安全装置」の線引き
（F-03-3-005、判断は 3b に送る）。** 確保・列挙を縛る上限は形が3種類に
割れている: `max_targets`（設定フィールド、目標数と heatmap セル数という
単位の違う2量を同じ値で縛る）、`max_degrees`（設定フィールドだが
`_MAX_DEGREES` で上限そのものにも絶対上限がある）、
`_MAX_VARIABLES_FOR_COUNT`（モジュール定数、利用側からは一切引き上げ不可）。
どれが「実験のために動かしてよい値」でどれが「動かせない安全装置」かの
一般則はこの文書にまだ無い。最小の是正として `IpcConfig.max_degrees` の
docstring に `_MAX_DEGREES` への相互参照を足した。`max_targets` の単位の
食い違い（目標数と heatmap セル数を同じ値で縛る）の解消は 3b に送る。

### 11.2 しきい値法の比較 —— 既定（D-27）を選んだ根拠（受け入れ条件3）

有限標本では、状態と無関係な目標に対しても決定係数は 0 にならない。目標を K 本
足せばその分だけ「容量」が積み上がるので、しきい値を課さない総容量は**目標を
何本並べたか**にも依存する量になる。既定はシャッフルサロゲート（D-27）で、
この節はその選択が実測でどこに効くかを記録する。

**一次資料は `results/03_capacity/meta.json` の `threshold_comparison`**
（`make figures-03` で再生成）と `capacity_profile.csv`。下の3つの表は
`tests/test_design_doc.py` がその2つと機械照合するので、**手書きの数値は1つも
残っていない**。散文の側には有効数字を書かず、表を指す。

代表条件は 3-B（IPC 掃引）の格子の中央点で、ρ = 0.95 / リーク率 = 0.6 / N = 50 / T = 100,000 / σ_u = 0.2、レプリケート 0。
**掃引の格子の点をそのまま使う**ので `capacity.csv` に同じ条件の行が必ず在り、
既定モードの数値が本番成果物と一致することまで機械照合できる
（`tests/test_capacity_threshold.py::test_default_mode_matches_the_committed_capacity_row`）。
比較専用の条件を別に作ると、この突合ができない。

**MC（線形メモリ容量、`diagnostics.memory_capacity`）**

| `threshold_mode` | `mc_total` | `mc_total_raw` | `mc_threshold` | `mc_effective_delay` |
|---|---|---|---|---|
| `none` | 11.7138 | 11.7138 | 0.000000 | 13.6280 |
| `surrogate`（既定） | 11.5439 | 11.7138 | 0.000736 | 10.5268 |

**IPC（情報処理容量、`diagnostics.ipc`）**

| `threshold_mode` | `ipc_total` | `ipc_total_raw` | `ipc_linear` | `ipc_nonlinear` | `n_targets_kept` | `ipc_threshold_degree1` |
|---|---|---|---|---|---|---|
| `none` | 28.0817 | 28.0817 | 11.5450 | 16.5367 | 601 | 0.000000 |
| `surrogate`（既定） | 27.9179 | 28.0817 | 11.5391 | 16.3787 | 324 | 0.000742 |
| `chi2` | 27.9233 | 28.0817 | 11.5391 | 16.3842 | 330 | 0.000763 |

**MC に `chi2` が無いのは実装の穴ではない。** MC の目標は次数1だけで周辺分布が
1種類しか無く、サロゲートで足りる（`SUPPORTED_THRESHOLD_MODES` が
`(surrogate, none)` の2つ）。比較は診断ごとに**その診断が受理するモードだけ**を
回している —— 片方に無いモードを 0.0 で埋めると、成果物を読む側が
「chi2 を課したら MC が 0 になった」と読める形になるため。

サロゲートは**次数ごとに**閾値を推定し、`chi2` は自由度 N と標本数だけで決まる
**次数に依存しない1つの値**（`chi2_N(q) / T_eff`、Dambre 2012 SupMat 3.2）を使う。
代表条件でのサロゲートの次数別しきい値（`capacity_profile.csv` の `threshold` 列、
D-38）と、同じ条件の `chi2` の値:

| 次数 | 1 | 2 | 3 | 4 |
|---|---|---|---|---|
| `surrogate`（既定） | 0.000742 | 0.000739 | 0.000800 | 0.000855 |
| `chi2`（次数に依らず一定） | 0.000763 | 0.000763 | 0.000763 | 0.000763 |

**採否（既定 = サロゲート）の理由。**

1. **総容量では3法をほとんど区別できない。** IPC の総容量は3法で 1% と違わず、
   MC でも 2% に満たない（上の2表）。**本番条件で差が小さいのは、しきい値が不要だから
   ではなくリザバーが実際に容量を持っているからである** —— 入力と独立な状態では、
   しきい値後の総容量は生の 0.66〜3.52% まで落ちる（D-27 の 3a 実測、N=15 / T=3000 /
   目標 601 本）。`none` は「容量がある」と「目標を並べた」を区別できない。

2. **効くのは総容量ではなく、そこから読む量である。** `none` では目標が1本も
   落ちず（IPC 表の `n_targets_kept` が目標数そのもの）、MC の `mc_effective_delay`
   （容量重心 = 実効的な記憶長）は `surrogate` の約1.3倍に伸びる。長い遅延に並ぶ
   ノイズ床のセルが重心を引っ張るためで、**受け入れ条件1 が測っている量そのもの**
   が歪む。成果物の量にも効く: `capacity_profile.csv` は「しきい値後の容量が厳密に
   正のセルだけ」を書く（D-38）ので、`none` にすると全セルが正になり行数は約10倍に
   なる（本番の 118 条件で 21,812 行 -> 211,916 行）。

3. **`chi2` ではなくサロゲートを既定にする。** 総容量の差は `surrogate` との間で
   0.1% にも満たない（IPC 表）。違いは**次数方向の形**で、`chi2` は次数に依らず
   一定なので次数1・2 では `surrogate` より厳しく、次数3・4 では緩い（次数別の表）。
   その結果 `chi2` の方が保持する目標は多いが、増えているのは高次側である。
   D-27 が次数ごとに閾値を推定するのは、有限標本のかさ上げ量が**目標の周辺分布**に
   依存するからで、その依存を漸近論で消すと次数分解（受け入れ条件4、§11.5）の
   読みが次数間で不揃いになる。**どちらを選んでも図の結論は変わらない**ので、
   選択の理由は結論の差ではなく「次数分解を歪めないこと」にある。

4. **サロゲートの代償は乱数と実行時間である。** `ctx.seed` が必須で、無ければ
   `ValueError`（D-27）—— しきい値が黙って非再現になる経路を塞いである。
   全条件が1個のシードを共有する（D-37、共通乱数法）ので、条件間の容量差に
   しきい値の推定ノイズが独立に乗ることはない。

### 11.4 NARMA10 の採用式・先行との差分・参照値の扱い

**採用した漸化式**（D-29。記事にはこの式をそのまま載せる）:

```
y[t+1] = 0.3 y[t] + 0.05 y[t] Σ_{i=0}^{9} y[t-i] + 1.5 u[t-9] u[t] + 0.1
u ~ U[0, 0.5] i.i.d.
```

文献の添字は2系統（`1.5 u(n-9) u(n)` 系と `1.5 u(k-1) u(k-10)` 系）に割れており、
どちらを使ったかで数値が変わるのに明記されないことが多い。実験3-C の直接の先行
（Goudarzi 2014）がこの形なので比較可能性を優先した。係数と入力分布は
`tasks/narma.py` のモジュール定数で、設定フィールドにはしない（D-29）——
YAML の1行変更で「記事に載せた式」と成果物の対応が黙って切れる経路を作らないため。
正しさは**実装のループでも実装の定数でもなく**、1ステップずつ書き下した有理数
（`Fraction`）の式との照合で固定してある（`test_matches_reference_recurrence`）。

**発散はクリップせず `ValueError`**（D-30）。宣言した分布 `U[0, 0.5]` の**内側**でも
NARMA10 は普通に発散する（`np.random.default_rng(s)` の s=0..199 のうち6本、
定数入力 0.5 は 33 ステップで発散）。黙ってクリップすると「クリップの飽和特性」
という別の非線形性を手法に与えることになり、遅延線対照が不当に有利／不利になる。
本番の task ストリームではレプリケート 0〜6 が発散せず 7 で発散するので、
`narma.base.n_replicates` を 7 以上にすると D-30 で落ちる
（`test_production_replicates_do_not_diverge` が両方を実測している）。

**先行との差分。** 3-C は先行の再現ではなく、**探索予算をそろえた対照**である:

| 項目 | 3-C | 先行の典型 |
|---|---|---|
| リザバー規模 | N = 50（D-39。3-B の IPC 掃引と同一規模） | 論文により 50〜1000 |
| 系列長 | T = 8000（訓練/検証/テストは D-05 の連続分割） | 数千〜数万、分割の記述は様々 |
| 対照 | 線形回帰・遅延線（リッジ / OLS）・ESN が**同一の分割**を通る。alpha 格子も共有し、例外は正則化なし水準の alpha = 0 だけ（D-04 / D-05 / D-08 / D-90） | 対照が無い、または探索予算が非対称 |
| 誤差指標 | NRMSE 主・NMSE 併記（D-02） | NMSE が多い（正規化の定義が書かれないことがある） |

**参照値の出典（特定済み、D-100）。** 図に引く参照値は NMSE = 0.16 と 0.107 の2つで、
長く「複数の物理 RC 論文が引用する値だが原典未特定」として扱っていた（要件_rc-basics-03
未確定1 / survey 未解決1）。**辿った結果、どちらも同じ論文に行き着いた。**

| 値 | 出典 | 測定条件（原典の記述） |

| **0.107 ± 0.012** | Vinckier et al. (2015), *High-performance photonic reservoir computer based on a coherently driven passive cavity*, Optica **2**(5):438 —— **同論文自身の実験値** | `N = 50` 内部変数、訓練 1000 ステップ / テスト 1000 ステップ、10 回反復 |

### 11.6 IPC の偶数次が空である理由 —— 駆動入力の対称性（3-S / D-116）

記事03 §2.1 は「次数2と4のセルがほぼ空」と述べるが、その理由は長らく**未検証**
だった（連載の規律により、確かめるまで本文に書けない）。仮説は「駆動入力が
ゼロ対称（一様・平均0）で tanh が奇関数なので、状態が入力の奇関数になり、
偶数次の目標と相関しない」である。

`make symmetry-03`（`results/03_capacity/capacity_symmetry.csv`、60 行）で実測した。
**振るのは駆動入力の平均のずれだけ**で、分布の形（一様）も標準偏差（`sigma_u`）も
変えない。一様のままなら `orthonormal_basis` が実測の平均・標準偏差で標準化した
あとも Legendre 基底は厳密に正規直交であり、D-28 を満たしたまま測れる。
**分布の形を歪める設計は採らなかった** —— 目標同士が直交しなくなって容量が
二重計上され、「偶数次が増えた」のか「二重計上が増えた」のかを分離できないため。

条件は rho=0.95 / leak=1.0 / sigma_u=0.2 / N=50 / T=30,000 / 3 レプリケート平均。

| オフセット（× sigma_u） | 実測平均 | 次数1 | 次数2 | 次数3 | 次数4 | 合計 | 偶数次の割合 |
|---|---|---|---|---|---|---|---|
| 0.0（ゼロ対称） | −0.0006 | 15.158 | **0.040** | 16.488 | **0.030** | 31.716 | **0.2%** |
| 0.5 | +0.0994 | 14.208 | 10.963 | 9.432 | 0.380 | 34.983 | **32.4%** |
| 1.0 | +0.1994 | 13.059 | 17.161 | 6.041 | 0.476 | 36.737 | **48.0%** |
| 2.0 | +0.3994 | 11.463 | 20.161 | 5.249 | 0.469 | 37.343 | **55.2%** |
| 3.0 | +0.5994 | 10.519 | 19.823 | 5.906 | 0.480 | 36.727 | **55.3%** |

**仮説は支持された。** ゼロ対称では偶数次が総容量の 0.2%（次数2 が 0.040、
次数4 が 0.030）にとどまるのに対し、平均を 0.5 sigma_u ずらすだけで 32.4%、
2 sigma_u 以上では 55% で頭打ちになる。分布の形は変えていない（実測の標準偏差は
全点で 0.2 のまま）ので、効いているのは**動作点がゼロから外れたこと**である。
tanh が奇関数なのは 0 のまわりだけなので、対称性の破れはここに入る。

独立な傍証が既存の成果物にある。**3-C（NARMA10）は入力が `U[0, 0.5]`**
（平均 0.25 = 1.25 sigma_u 相当、`tasks/narma.py` の D-29）で、`capacity_profile.csv`
では次数2 の合計 14.38 が次数1 の 10.46 を**上回っている**。上の表で
offset = 1.0〜2.0 の領域に対応し、独立に測った実験が同じ向きを示している。

判定は図ではなく行の値から出る（`experiment/symmetry.py::even_degree_share`）。
`tests/test_experiment_symmetry.py::test_breaking_the_symmetry_makes_the_even_degrees_appear`
が仮説そのものを guard_test として固定しており、**落ちたら理由は対称性ではなく
基底の構成か打ち切りの側にある**（その場合は D-116 の見直しが先）。

### 11.5 実測結果 —— 容量・図の読み方・実行時間・較正記録

#### 3-A: MC は ρ とともに伸びるが N には遠く届かない（受け入れ条件1）

`fig_mc_sweep.png` の**上限線 y = N はスケールの参照であって到達目標ではない**。
本番設定（N = 200 / T = 20000 / σ_u = 0.1）で `mc_total / N` が到達する最大は **18.9%**（最小 5.3%）で、
MC は N に漸近するのではなく、ESP が保たれる範囲で **ρ を上げると単調に伸びる**。
上限線を「そこまで届くはずの線」と読むと図の主張を取り違える。左パネルの縦軸を
対数にしてあるのはこのためで、上限線と実測を線形軸に同居させると実測側が潰れる。

`mc_effective_delay`（容量重心 = 実効的な記憶長）のレプリケート平均:

| リーク率 \ ρ | 0.5 | 0.7 | 0.9 | 0.95 | 1.0 | 1.1 | 比（最大ρ/最小ρ） |
|---|---|---|---|---|---|---|---|
| 0.3 | 20.99 | 30.63 | 49.62 | 58.95 | 69.40 | 60.24 | 2.87 |
| 0.6 | 11.78 | 15.80 | 22.06 | 25.00 | 35.73 | 26.98 | 2.29 |
| 1.0 | 9.20 | 11.64 | 16.29 | 18.19 | 21.74 | 21.37 | 2.32 |

**ρ = 1.1 で下がるのは異常ではない。** 駆動が弱いと ρ > 1 では ESP が成立せず、
記憶容量は臨界点近傍で最大になってから落ちる（02 の §9.5 と同じ現象の別の見え方）。
受け入れ条件1 の「単調非減少」を **ρ <= 1.0 に限る**のはこのためで、**D-40** として
記録してある（guard_test は ρ = 1.1 が格子の最大値**でない**ことまで見る —— 単調性を
ESP 領域に限る根拠が消えたら赤くなる）。表の右端の比は仕様が要求する 1.5 倍以上を
3本とも満たす。

#### 3-C: 遅延線が ESN を上回った（§7 リスク3。**そのまま記録する**）

本番（N = 50 / T = 8000 / 5 レプリケート）のテスト誤差のレプリケート平均:

| 手法 | NMSE | NRMSE | 選ばれた探索点 |
|---|---|---|---|
| 線形 | 1.0181 | 1.0090 | alpha=100.0 (5/5) |
| 遅延線（リッジ） | 0.1538 | 0.3920 | k=30 (4/5), k=25 (1/5) / alpha=1e-10 (2/5), alpha=1.0 (2/5), alpha=10.0 (1/5) |
| 遅延線（OLS） | 0.1534 | 0.3915 | k=30 (4/5), k=25 (1/5) / alpha=0 (5/5) |
| ESN | 0.2673 | 0.5170 | alpha=1e-10 (3/5), alpha=1e-09 (1/5), alpha=1e-07 (1/5) |

**遅延線が ESN を上回った。** 線形回帰は NMSE がほぼ 1（= 平均を答えるのと同等）で
無力、遅延線は §11.4 の参照値「非線形性なしの天井」をわずかに下回り、ESN は
「良好な非線形 RC」に届いていない。結果の向きは問わない設計にしてあり
（`meta.json` の `narma10_verdict` は勝敗を両方向とも同じ形で書く）、**このまま
記録する**。

**正則化は優位の理由ではなかった（D-90）。** 先行（Goudarzi et al. 2014）の対照は
正則化なしの遅延線だったので、**同一の特徴・同一の分割で alpha だけを 0 に固定した
第4水準**を足した（設計行列は遅延線から借りるので、既存3手法の値は1つも動かない）。
結果は NMSE = 0.1534 で、リッジ版（0.1538）とほぼ同値のまま ESN を下回る。
`meta.json` の `regularisation_changes_the_verdict` は `false` である。

つまり「遅延線が勝つのは正則化を入れたからだ」という説明は**この規模では成り立たない**。
先行との差は正則化の有無ではなく、タップ数の側にある（先行は 1,810 タップ固定、
ここでは検証分割が k = 25〜30 を選ぶ）。

#### 3-C': タップ数を振ると先行の対照設計の穴が再現する（D-95）

上の段落は当初「と読むのが実測に合う」で終わっていた。**読みではなく実測にした**のが
3-C' である。3-C の動作点は `k / n_train ≤ 0.01` で、先行の `k / n ≈ 0.9`
（1,810 タップ / 訓練 2,000 点）には届いていない。**この領域では OLS が壊れる理由が
無い**ので、「OLS でも同じだった」だけでは先行の対照設計を検証したことにならない。

そこでタップ数の軸を振る。各 k は独立に `plan_replicate` を通るので `t0` もその k の
ものになり、k が伸びるほど訓練区間が縮んで `k / n_train` が自然に 1 へ近づく。
2つの水準は**同一の特徴・同一の分割**で、`alpha` だけが違う。

| k | 10 | 30 | 100 | 300 | 800 | 1500 | 2200 | **2500** |
|---|---|---|---|---|---|---|---|---|
| `k / n_train` | 0.003 | 0.008 | 0.026 | 0.080 | 0.229 | 0.476 | 0.786 | **0.943** |
| OLS / リッジ の NMSE 比 | 1.00 | 1.00 | 1.02 | 1.02 | 1.04 | 1.40 | 1.60 | **3.33** |

小さい k では両者が区別できず、`k / n_train` が 1 に近づいたところで **OLS だけが
壊れる**。したがって先行の対照設計の穴は「正則化なし」単独ではなく
**「正則化なし かつ k ≈ n_train」の合わせ技**である、と実測で言える。

掃引の上限 2500 は `k + 1 > n_train` で正規方程式が構造的に特異になる手前で止めたもの
（実測: k = 2600 で `n_train` = 2600 になり scipy が singular matrix を送出）。
`run_narma10_tap_sweep` はこれを**解く前に** `ValueError` で落とす —— scipy の
`LinAlgError` は「どの k がなぜ悪いのか」を言わず、掃引の設計を直せないためである。
判定は全レプリケートの最小 `n_train` で行う（分割オフセットがレプリケートごとに違うので、
1本だけ通って他が落ちる形にしない）。

**容量が成績を説明する。** 同じ ESN の容量は `capacity.csv` の `3C_narma10` 行に
あり、成績（`narma10.csv`）と条件キーで join できる:

| 量 | 値 |
|---|---|
| `mc_total`（線形メモリ容量） | 11.1534 |
| `mc_ratio` = `mc_total` / N | 0.2231 |
| `mc_effective_delay`（容量重心） | 22.4577 |
| `ipc_total`（総容量） | 30.2528 |
| `ipc_linear`（次数1） | 10.4619 |
| `ipc_nonlinear`（次数2以上） | 19.7910 |

読みは2段ある。

**(1) 記憶の量そのもの。** NARMA10 は `u[t-9]` と `u[t]` の積を含むので 10 ステップの
記憶が要る。遅延線は選ばれた k（上表）だけ**完全なタップ**を読み出しに与える ——
過去 k ステップを劣化なしで持つ —— のに対し、同じ課題を解く ESN の線形メモリ容量は
上表の `mc_total` しかない（N の2割強）。

**(2) 容量の使い道。** ESN は総容量の**大半を非線形に使っている**（上表の
`ipc_nonlinear` が `ipc_total` の約3分の2で、`ipc_linear` はその半分強）。
NARMA10 が要求する非線形性は `u[t-9] u[t]` の1項（次数2）が主なので、**この課題が
あまり必要としない非線形性に容量の大半が割かれている**。遅延線は逆に、容量の
すべてが線形の記憶であり、それがこの課題では効く。

**これは連載の主題そのものである。** 「リザバーは非線形性と記憶をトレードオフ
する」という主張が、成績（NMSE）と容量（MC / IPC）という別々に測った2枚の CSV を
突き合わせるだけで読める形になっている。**ESN が負けたことは失敗ではなく、
容量測定という道具が成績を説明できたという結果**である。

**限界（この結果で言えないこと）。**

- **遅延線の真の最適は測れていない。** k = 30 は探索格子 `(10, 15, 20, 25, 30)` の
  **上端**で、4 / 5 回それが選ばれている（張り付き）。上端を
  広げれば遅延線はさらに良くなる可能性がある。格子を動かさなかったのは要件書が
  「タップ数を妥当な範囲 (k=10〜30) に抑え」と指定しているためで、01 の `n_lags`
  上端拡張（§8.2）とまったく同じ論点が 3-C にも残っている。
- **探索予算が非対称で、しかも遅延線に有利な側に倒れている。** D-08 により構造 HP は
  検証分割で選ばないので、遅延線は alpha × k = 13 × 5 = 65 点、ESN は
  alpha のみの 13 点を探索する。仕様 §7 リスク3 の指示どおり**追加条件は回して
  いない** —— ρ / リーク率 / N を振って ESN 側を良くする探索は、その非対称性を
  逆向きに作り直すことにしかならない。
- **ESN は宣言した1点しか報告していない。** N は D-39 で宣言した1点で、§11.4 の
  参照値が N = 50 規模であることに合わせたものである（D-08 により N は検証分割で
  選ばれない）。
#### 駆動強度 σ_u の較正記録

`sigma_u` は**セクションごとに持つ**（§3.2）。MC の ρ 依存は準線形域を要し、IPC の
次数分解は中程度の駆動を要するので、最適な動作点が一致する保証が無いためである。
**図をまたいだ絶対値比較はしない。**

3-A の `sigma_u` は受け入れ条件1（`mc_effective_delay` が ρ とともに伸びる）を
満たす**最小値**として選んだ。代表条件（ρ ∈ {0.5, 0.99}・リーク率 1.0・1レプリケート）
での較正の実測:

| 0.05 | 9.29 | 24.68 | 2.66 | 代表条件では満たすが**本番格子で不成立**（リーク率 0.3 で 64.49@ρ=0.95 -> 63.46@ρ=1.0） |
| **0.1** | 9.04 | 20.37 | 2.25 | **成立（採用）** |
| 0.2 | 8.39 | 15.11 | 1.80 | 成立（ただし最小ではない） |
| 0.5 | 6.50 | 9.09 | 1.40 | **不成立**（比が 1.5 未満） |

代表条件だけで選ぶなら最小は 0.05 だが、受け入れ条件1 は**本番格子に対する主張**
なので「本番格子でも成立する最小値」を採った。**この表だけはコミット済みの成果物に
残らない一回性の実測である**（較正のために本番格子を4通り回したもの）。
再現手順は `docs/plans/rc-basics-03b.md` の T2 実装メモ 4・6 に、格子ごとの

`ipc_sweep` / `conservation` / `length_sweep` の `sigma_u` = 0.2 は
受け入れ条件4（次数分解）側の動作点であり、この較正の対象ではない。

#### 公開 API の命名規約とレイヤ境界（04a T2、D-52 / D-53）

*一次資料: `docs/adr/0001-t2-noise-propagator-and-public-api-boundaries.md`（Accepted）。
`§12` は 04b の自由走行予測のために空けてある。*

**レイヤの依存方向**（辺の種類を分けて読む）:

```
types -> config / seeds / metrics -> reservoir / readout / tasks / diagnostics
      -> experiment ==(静的)==> plotting
                    <-(動的)--
```

| 辺 | 種類 | 何を運ぶか | 書き方 |
|---|---|---|---|
| `plotting -> experiment` | **静的** | 行 dataclass の型・集計関数（`aggregate_nrmse` / `mean_nrmse_by_washout`）・記事メタの文言 | module-level import（**許可**） |
| `experiment -> plotting` | **動的** | 図を描く関数の呼び出しだけ。型注釈にも定数にも現れない | **関数本体の中**で import（D-53） |

両方を module-level で書くと
`plotting/__init__ -> plotting.figures -> experiment.runner -> experiment/__init__
-> experiment.pipeline -> plotting.figures`（部分初期化）で循環し、
`import rc_basics_lab.plotting` **単独**が `ImportError` になる。動的な辺だけを
関数本体へ落とせば、公開 import 経路を1つも変えずに循環が消える（3ファイル・6行）。

受け入れ基準は仕様（`import` が通ること）より**強くしてある**: `plotting/__init__` を
遅延化しただけでも `import` は通るが、`ImportError` は最初の属性アクセスへ
1回ぶん移動するだけである。実測（案A を実装して D-53 を取り消した状態）:
`test_plotting_can_be_imported_first` は**緑**、
`test_every_package_resolves_all_of_its_public_names_when_imported_first[plotting]` は
**赤のまま**。したがって guard は「単独 import 後に `__all__` の**全名前**が
解決すること」を7パッケージすべてで測る。

**命名規約（D-52）**: どのパッケージでも、**公開サブモジュール名と同名の公開
シンボルを `__init__` で再エクスポートしない**。診断層の対応は以下で、
モジュール名と関数名が衝突する2件だけが `__init__` から外れている。

| モジュール | 公開する診断関数 | `diagnostics.<名前>` が指すもの | `__all__` に関数を載せるか |
|---|---|---|---|
| `dummy` | `state_mean_norm` | モジュール | 載せる（衝突なし） |
| `state_space` | `state_pca` | モジュール | 載せる（衝突なし） |
| `esp` | `esp_convergence` / `conditional_lyapunov` | モジュール | 載せる（衝突なし） |
| `timescale` | `autocorrelation_time` | モジュール | 載せる（衝突なし） |
| `memory_capacity` | `memory_capacity` | **モジュール** | **載せない**（同名） |
| `ipc` | `ipc` | **モジュール** | **載せない**（同名） |
| `lyapunov`（04b-1 で追加） | `lyapunov` は**禁止**（`max_lyapunov` 等にする） | モジュール | — |

`from .ipc import ipc` と書くと、パッケージ属性 `diagnostics.ipc`（=モジュール）が
**関数**で上書きされる。`import a.b.c as m` は `sys.modules` より先に親の属性を
見るため `m` は関数になり、`monkeypatch.setattr(m, "...")` が関数オブジェクトへの
属性設定として**成功**したまま何も差し替わらない —— 3a のレビューで実際に踏み、
**変異試験が偽の緑になった**。関数の正規の入手経路はフルパス
（`from rc_basics_lab.diagnostics.ipc import ipc`）1本に固定する。設定と既定値
（`IpcConfig` / `DEFAULT_IPC` など）はモジュール名と衝突しないので従来どおり。

**ノイズ経路の封鎖（D-47 / D-48）** も同じ ADR で決めた。02 の経路に
`state_noise>0` を入れると壊れ方が2種類あり、どちらも `ValueError` で塞ぐ:

| 場所 | 拒否する理由 | 正しい経路 |
|---|---|---|
| `esn_propagator`（D-48） | `conditional_lyapunov` は摂動の成長率を測るので伝播器は決定的でなければならない。ノイズを入れると「摂動 + ノイズ実現値の差の成長率」という別の量になる | `state_noise=0` で ESN を構成する |
| `simulate_condition`（D-47） | 比較軌道に D-14 の3ストリームの外側から4本目の変動が混ざる／乱数消費が参照軌道に依存するので結果が**評価順**に依存する | `simulate_reference_trajectory(..., state_noise=...)`（3-B' と同じ） |

「ノイズ無しの複製で伝播する」は安全に見えて**成立しない**。ノイズ有りの参照軌道に
ノイズ無しの複製を当てたときの RMS/ユニット不一致量の実測（N=60 / ρ=0.9 /
leak=0.3 / T=300）:

| `state_noise` | 不一致量（最悪値） | `propagator_tol`=1e-10 に対して |
|---|---|---|
| 1e-4 | 2.741e-05 | **5.44 桁**超過 |
| 1e-3 | 2.741e-04 | **6.44 桁**超過 |
| 1e-2 | 2.742e-03 | **7.44 桁**超過 |

つまり `check_propagator=True` では必ず落ち、しかもメッセージは「参照軌道と別の
入力で伝播している疑い」という**誤った診断**になる。この実測は
`test_noise_free_clone_fails_the_propagator_check` が保持していて、
却下の理由が次のサイクルで失われないようにしてある。

#### カオス系の生成・Δt の較正・λ_max の推定（04b-1 T4、D-41 / D-42）

**Lorenz 系の生成**（`src/rc_basics_lab/tasks/chaotic.py`）:

| 項目 | 値 | 出どころ |
|---|---|---|

| 積分法 | 古典的 RK4（Python の float 3個で保持） | 同上 |
| 積分刻み `rk4_step` | 0.002 | `LorenzConfig` |

Mackey-Glass は **再実装していない** —— `tasks/mackey_glass.py`（τ=17、`rk4_step`
0.1、`sample_interval` 10）へ委譲し、04 が足すのは標準化だけである。

**Δt の較正**（代表条件: Lorenz / N=200 / ρ=0.9 / leak=0.3 / `state_noise`=0 /
自走 2000 ステップ / 10 レプリケート）。判定基準は受け入れ条件1（自走がアトラクタを
再現）と受け入れ条件3（1ステップ先で ESN と遅延線の差が小さい）の**両方**が
成立すること:

| `sample_interval` | Δt | 1ステップ先 NRMSE（線形 / 遅延線 / ESN） | ESN/遅延線 | 自走の破綻 | 有効時間 [λ_max^-1] | std 比 |
|---|---|---|---|---|---|---|
| **5（採用）** | **0.01** | 0.0603 / 1.8e-05 / 5.1e-05 | **2.93** | **0/10** | **4.74** | **0.998** |
| 10（落選） | 0.02 | 0.1225 / 3.3e-04 / 2.6e-04 | 0.78 | **5/10** | 2.25 | 1.329 |
| 25（落選） | 0.05 | 0.3035 / 5.4e-02 / 2.2e-03 | **0.040** | 4/10 | 1.72 | 1.299 |

- **10 は受け入れ条件1 を満たさない**: 10 本中 5 本の自走が真値スケールの5倍を超えて
  発散する（`std` 比 1.33 も、残った軌道がアトラクタより広がっていることを示す）
- **25 は受け入れ条件3 を満たさない**: ESN が遅延線を **25 倍**上回り、「1ステップ先
  予測では差がつかない」という連載の問題意識そのものが成立しない
- **5 は両方を満たす**: 破綻 0/10、自走軌道の成分ごと標準偏差は真値の 0.998 倍、
  ESN と遅延線は絶対値で 2e-05 と 5e-05（どちらも線形ベースライン 0.060 の
  1/1000 以下）。線形が 0.060 に留まることは、Δt を小さくしすぎて課題が自明に
  なってはいないことの裏付けでもある（要件書 未確定1）

参考として `state_noise = 1e-3` も測った（4-C の掃引軸の先取りではなく、
「破綻はノイズで直せるので Δt を選ばなくてよい」という誤った結論を排除するため）:
`sample_interval=10` の破綻は 5/10 → 2/10 に減るが**ゼロにはならず**、有効時間は
2.25 → 1.93 に落ちる。`sample_interval=5` ではノイズを入れると有効時間が
4.74 → 2.73 に落ちるので、**本番の基準点は `state_noise = 0`** とする。

**λ_max の数値推定**（`src/rc_basics_lab/diagnostics/lyapunov.py`、D-42）:

- 手法: Benettin 法（`conditional_lyapunov` と同一の反復）。摂動 δ = 1e-8
  （RMS/ユニット距離）、再正規化間隔 10 サンプル、軌道長 8000 サンプル
  （= 80 時間単位、800 区間）、burn-in は `integration_burn_in` の 1000 サンプル
  （`ctx.washout` は 0。二重に捨てない）
- 伝播器は `lorenz_sample_step`（1サンプル = 5 RK4 ステップ）。生成と同一の演算列を
  通るので `propagator(X[t], t)` は `X[t+1]` と**ビット一致**し、D-18 の伝播器整合
  検査（`propagator_tol` = 1e-10）を厳密に通る
- 軌道は**標準化していない生の状態**を使う（成分ごとに違う倍率で割ると有限時間の
  成長率が座標系に依存する）
- **実測: λ_max = 0.9161 [1/時間]**（Lyapunov 時間 1.0916）。文献値
  **0.9056**（D. Viswanath, *Lyapunov Exponents from Random Fibonacci Sequences to
  the Lorenz Equations*, Ph.D. thesis, Cornell University, 1998）との相対差は
  **1.16%**（許容 5%）
- **正本は数値推定**であり、文献値は `MaxLyapunovConfig.reference_value` として
  照合にしか使わない。`reference_value` を 42.0 にしても推定値は1ビットも動かない
  ことをテストが実測する

### 12.2 有効予測時間（D-43）と閾値の感度

誤差は**瞬時の NRMSE 比** `e[k] = rms_j(y_hat[k,j] - y[k,j]) / std(y)` で、分母は
`metrics.nrmse` と同じ「真の系列の標準偏差（ddof=0、全成分をまとめて）」である
（D-02 の指標を 04 で作り直さない）。`e[k]` が初めてしきい値を超えるまでのステップ数を
**Lyapunov 時間 `1/λ_max` で割って**報告する。自走長（2000 ステップ）まで超えなければ
`valid_time_censored = True` を立てる（**打ち切りを無かったことにしない**）。

Lorenz / ESN / 10 レプリケートの閾値感度（`meta.json` の `valid_time_sensitivity`）:

| しきい値（NRMSE 比） | 中央値 [λ_max^-1] | 最小 | 最大 | 打ち切り |
|---|---|---|---|---|
| 0.2 | 3.71 | 2.97 | 5.57 | 0 |
| 0.3 | 4.74 | 3.14 | 5.90 | 0 |
| **0.4（採用）** | **4.83** | **3.18** | **5.93** | **0** |
| 0.5 | 5.24 | 3.67 | 5.95 | 0 |
しきい値を 0.2 から 0.5 へ動かしても中央値は 3.71 → 5.24 の範囲に収まり、**対照との
差（下記）に比べて桁が2つ小さい**。「0.4 だから出た結論」ではない。

**文献と並べるときは 0.3 の行を使う（D-101）。** RC のカオス予測で使われる有効予測時間
（VPT）の一次資料は Platt et al. (2022) *Neural Networks* 153:530 で、定義は

> RMSE(t) = sqrt( (1/D) Σ_i [ (u_i^f(t) − u_i(t)) / σ_i ]² ) > ε,  ε は "arbitrarily to 0.3"

である。**平方根が入っている**のでこちらの NRMSE 比（D-43）と同じ次元であり、閾値も 0.3
なので、**格子に元から入っていた 0.3 がそのまま比較点**になる。その値は **4.74**。

ただし正規化の仕方は完全には一致しない。一次資料は**成分ごとに** `σ_i` で割ってから
D 次元で二乗平均するが、こちらは真の系列の標準偏差1つで割る。Lorenz は成分ごとに分散が
違うので、同じ閾値でも厳密に同じ量ではない。

**参照線は別の一次資料から引いた（D-102）。** Platt et al. は L63 の VPT を図
（Figure 4 左 / Figure 5）の分布として示すだけで本文に単一の代表値が無い（条件は読み取れ、
Figure 4 は `N = 2000`、Figure 5 に `N = 250` の系統、いずれも 200 個のテスト初期条件）。
そこで2本目を当たった。

**Gauthier, Bollt, Griffith, Barbosa (2021)** *Next generation reservoir computing*,
Nat. Commun. **12**:5564 の本文にはこうある:

> The NG-RC forecasts well out to ~5 Lyapunov times.

同じ段落が「**comparable to an optimized traditional RC with 100s to 1000s of reservoir
nodes**」と述べており、こちらの `N = 200` はその範囲に入る。単位もそろっている ——
同論文の Lorenz63 の Lyapunov 時間は **1.1 時間単位**で、こちらの数値推定
（`1/λ_max = 1/0.9161 = 1.0916`）と実質一致する。

| | こちら（4-B） | Gauthier et al. 2021 |
|---|---|---|
| 有効予測時間 | **4.83**（ESN 中央値） | **~5** |
| リザバー規模 | `N = 200` | 従来型 RC で 100〜1000 ノード相当 |
| Lyapunov 時間 | 1.0916（数値推定） | 1.1 |
| 判定基準 | NRMSE 比 0.4（D-43） | 「forecasts well」（**定量的に未明示**） |

**判定基準だけが一致しない**ので、その旨を参照線の動作点として凡例に入れてある（D-97）。
比は目安として読むこと。

同じしきい値 0.4 での手法別（Lorenz、中央値 [λ_max^-1]）:

| 手法 | 中央値 | 最小 | 最大 |
|---|---|---|---|
| 線形 | 0.069 | 0.027 | 0.137 |
| 遅延線 | 0.179 | 0.101 | 0.486 |
| **ESN** | **4.83** | **3.18** | **5.93** |

**Mackey-Glass の行は Lyapunov 正規化していない**（`lyapunov_time` も
`valid_time_lyapunov` も `nan`）。λ_max を数値推定してあるのは Lorenz だけで、MG の
Benettin 法には遅延系の履歴（τ/h = 170 次元）を状態とする伝播器が要る。**推定して
いない量を他の系の値で埋めない**（D-42 の「正本は数値推定」の裏返し）。MG の有効
予測時間は `valid_time_steps` と `valid_time`（MG の Δt = 1.0）として出る。

### 12.3 アトラクタ再現の定量化（D-46）—— 2指標とシャッフル代替

**視覚評価は結論に使わない**。2本の距離を測り、どちらも**真の軌道のシャッフル代替**
（時間順序だけを壊し、周辺分布は1ビットも変えない対照）より小さいことを要求する。

1. **リターンマップの距離**: 最終成分の連続する極大値の対 `(z_n, z_{n+1})` の点集合に
   対する**対称 chamfer 距離**
2. **パワースペクトルの距離**: 成分ごとに平均を引き Hann 窓をかけて `rfft` を取り、
   総和1へ正規化して成分平均したスペクトル間の**全変動距離**（0 が完全一致）

実測（`meta.json` の `attractor_verdict`、10 レプリケート）:

| 課題 | 手法 | 代替より近い | リターンマップ（自走 / 代替） | スペクトル（自走 / 代替） |
|---|---|---|---|---|
| Lorenz | 線形 | 0/10 | 1.9438 / 0.4296 | 0.9288 / 0.9321 |
| Lorenz | 遅延線 | 0/10 | 1.5530 / 0.4296 | 0.8589 / 0.9321 |
| **Lorenz** | **ESN** | **10/10** | **0.0181 / 0.4296** | **0.3853 / 0.9321** |
| Mackey-Glass | 線形 | 0/10 | nan / 0.1705 | 0.9999 / 0.9457 |
| Mackey-Glass | 遅延線 | 0/10 | 0.7763 / 0.1705 | 0.7059 / 0.9457 |
| **Mackey-Glass** | **ESN** | **10/10** | **0.0061 / 0.1705** | **0.2994 / 0.9457** |

10 本が全部同じ向きなので片側符号検定の p は **1/1024 = 0.00098**（`sign_test_p`）。
これが「**有意に**近い」の中身である。対照が 0/10 であることも同時に測る —— 対照でも
成立するなら、指標が自走の質を見ていない。

**2次元ヒストグラムの全変動距離を採らなかったのは実測による**。真の軌道の極大値は
20,000 サンプルでも約 106 点しかなく、同一分布からの独立標本（真の点列を半分ずつに
割ったもの）でも TV が 0.23〜0.45（ビン 8〜32）に達して自走（0.14〜0.26）と重なる。
同じ対照で chamfer は **0.030（同一分布）/ 0.011（自走）/ 0.393（シャッフル代替）**と
分離する。標本数が三桁のとき、ヒストグラム距離の雑音床は信号と同じ大きさになる。

**`stats_steps` を長時間統計の長さとして 20,000 に決めた根拠**（Lorenz / ESN /
10 レプリケート / リターンマップ距離）:

| `stats_steps` | 時間単位 | λ_max^-1 単位 | 中央値 | 最大 | 備考 |
|---|---|---|---|---|---|
| 2,000 | 20 | 18 | 0.042 | 0.083 | 全レプリケートが良好 |
| 5,000 | 50 | 46 | 0.024 | 0.051 | 同上 |
| 10,000 | 100 | 92 | 0.021 | 0.240 | 1/10 が崩れ始める |
| **20,000（採用）** | **200** | **183** | **0.018** | **0.412** | **3/10 が崩れる** |

**短い方が「きれいな結果」になる**ので、あえて長い方を採った。判定基準は
「真の系列（8,000 サンプル）より長く、かつ 100 Lyapunov 時間以上回す」で、結果を
見てから決めていない。長く回すと 10 本中 3 本（レプリケート 0 / 2 / 5）の自走が
アトラクタから外れて収縮する（標準偏差比 0.84 / 0.80 / 0.96）が、それでも
**10/10 がシャッフル代替より近い**。この「長時間では崩れうる」性質は記事に書くべき
結果であって、隠す対象ではない。

### 12.4 3態分類の基準（D-45）

分類は**純関数 + 数値基準**で、図も目視も使わない。判定は上から順に排他で、最後の
分岐が残り全部を受けるので網羅する:

| 順 | 3態 | 条件 | 定数 |
|---|---|---|---|
| 1 | 発散 | 非有限で打ち切り **または** ピーク振幅 / 真値のピーク振幅 > 5.0 | `AMPLITUDE_RATIO_MAX` |
| 2 | 周期軌道 | 標準偏差比 < 0.2 **または** 自己相関のピーク >= 0.95 | `COLLAPSE_STD_RATIO` / `PERIODIC_AUTOCORR` |
| 3 | アトラクタ再現 | それ以外（有界かつ非周期） | — |

- **振幅を見るのが要点**。`float64` の範囲内で 1e200 まで伸びる軌道は有限値のままで、
  `isfinite` だけの判定は「発散していないが破綻した」軌道をアトラクタ再現に数える
  （T4 の Δt 較正で実際に踏んだ壊れ方）
- `COLLAPSE_STD_RATIO` は `AMPLITUDE_RATIO_MAX` の**逆数**である。倍率を2本持つと
  片方だけを動かせてしまい、「図が良く見えるまで閾値を動かす」余地が残る
- 自己相関は**最初のゼロ交差以降**の最大値を見る。Δt = 0.01 ではラグ1 の自己相関が
  0.999 に達する（滑らかにサンプルしているだけ）ので、そのまま最大を取ると全部が
  周期軌道になる

**閾値が結論を作っていないことの実測**（Lorenz、`stats_steps` = 20,000）:

| 群 | 標準偏差比 | 自己相関のピーク | 判定 |
|---|---|---|---|
| ESN の自走（10 本） | 0.80 〜 1.01 | 0.005 〜 0.224 | アトラクタ再現 10/10 |
| 遅延線の自走（10 本） | 0.032 〜 0.129 | -0.00 〜 0.256 | 周期軌道 10/10 |
| 線形の自走（10 本） | 0.041 〜 0.214 | 0.717 〜 0.760 | 周期軌道 9/10 |
| 4-C で発散した条件（100 本） | — | — | 振幅比の最小が 5.4 |

しきい値 0.2 は ESN（下限 0.80）と対照（上限 0.214）の**どちらからも遠い**。
線形の 1 本（標準偏差比 0.214）だけが「アトラクタ再現」側に落ちる —— 20,000 ステップ
かけてもまだ不動点へ収束しきっていない緩やかな渦である。**再現の可否を最終的に決める
のは D-46 の2指標**（この 1 本も 0/10 の側）で、D-45 は粗い3態にしか使わない。

### 12.5 4-C / 4-D —— 状態ノイズが領域を変え、容量は自走を説明しない

3態の内訳（`stability.csv` 320 行 / `meta.json` の `regime_counts_by_noise`）:

| 状態ノイズ | 発散 | 周期軌道 | アトラクタ再現 |
|---|---|---|---|
| 0 | 31 | 0 | 49 |
| 1e-04 | 28 | 0 | 52 |
| 1e-03 | 24 | 1 | 55 |
| 1e-02 | 32 | 1 | 47 |

**状態ノイズの効きは非単調である**（発散 31 → 28 → 24 → 32 / 80 条件）。中程度の
ノイズ（1e-04〜1e-03）では発散が減るが、最大のノイズ（1e-02）ではノイズ無しより
むしろ発散が増える。要件書 設計判断3（「ノイズ注入を入れずに『自走が不安定』と
結論すると誤り」）の核心 —— ノイズを掃引軸に含めないと自走の安定性を正しく評価
できない —— は実測で裏づけられたが、「ノイズを増やすほど単調に安定化する」という
単純な結論は成り立たない。格子点単位（(ρ, leak_rate) ごとの5レプリケート多数決）
で見ても、ノイズ無しと最大ノイズの間で変わるのは1点だけ（(ρ, leak_rate) =
(1.3, 0.6) が発散からアトラクタ再現へ変わる）で、他の点は変わらない。

4-D は 4-C と**同じ状態行列**に MC / IPC を当てる（条件ごとに ESN を2回作らない）。
3態ごとの有効予測時間の中央値 [λ_max^-1] は **アトラクタ再現 2.83 / 発散 0.84 /
周期軌道 0.71** で、3態は自走の質と整合している。一方 `mc_total` と有効予測時間の
関係は単調ではなく、**MC が最大（250〜350）の条件はほとんど発散側**にある
（`fig_stability_map.png` の右端パネル）。「記憶容量が大きいほど自走が上手くいく」は
成り立たない。

> **4-D の測定上の限界**（`meta.json` の `capacity_note` と同文）: 駆動が i.i.d. では
> なく決定的な Lorenz の x なので、MC / IPC が前提とする「遅延目標が互いに直交する」が
> 成り立たない。実測では `mc_total` も `ipc_total` も保存則（<= N = 200）を超える
> （最大 `mc_total` = 350 前後、`ipc_total` ≈ 600）。**04 の容量の絶対値は 03 の掃引
> とも保存則とも比較できない**。読めるのは同じ駆動の下での条件間の相対比較だけである。
> 03 の枠組みで絶対値を測りたければ、同じリザバーを i.i.d. 入力で別に駆動する必要が
> あり、それは「条件ごとに ESN を2回作らない」という仕様の禁止構造と衝突する。

### 13.4 実測（記事の結論）

- **AUPRC で一様乱数対照から離れるのはリザバー残差だけ**（MGAB、15 対の片側符号検定）。
  ESN 0.1602 ± 0.0130（対照比 2.83x、15/15、p = 3.1e-05）に対し、遅延線 0.0570 /
  直前値 0.0559 / 移動統計 0.0560 / 入力ノルム 0.0558 は一様乱数 0.0567 と区別できない
- **一様乱数の AUPRC は異常率に張り付いた**（0.0567 vs 0.0555）。これが
  「主指標が point-adjust を通っていない」ことの実測的な証拠になる（D-54 / D-55）
- **プロトコル 27 格子点のうち 23 点で順位が動いたが、逆転 62 組のうち
  「両方に印がある」組は 0 組**で、ESN の順位は 27 点すべてで1位だった（D-78）。
  順位の変動だけを報告すると**逆の結論**になる
- **`n_units_at_90pct` = 100**（基準 N=200 の AUPRC 0.1602 に対し N=100 で 0.1392 =
  0.869 倍、N=50 で 0.585 倍、N=25 で 0.469 倍）。全 24 行が `n_train=14800` で
  学習量は揃っている（D-80）

数値の正本は `results/05_anomaly_detection/`（`meta.json` と CSV5枚）で、
README の表は `tests/test_readme_summary.py` が同じ CSV と機械照合する。
