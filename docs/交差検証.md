# 交差検証で alpha を選ぶ

**既定では使っていません。** `results/` の成果物は単一の検証区間で作られており、
選び方を変えると記事の数値が変わるためです。手元で試すには:

```bash
uv run python experiments/01_what_is_rc/run.py --set ridge.cv.n_folds=4
```

## 時系列では素朴な k-分割を使えません

漏れが 3 通り起きます。

| 漏れ | 何が起きるか | 対処 |
|---|---|---|
| **未来 → 過去** | 検証区間より後ろの行で学習すると、予測しようとしている時刻より後の情報が係数に入る | `rolling`（原点を進める）は構造上作れない |
| **ラグ** | 設計行列の 1 行は過去 `n_lags` 行の入力を含むので、訓練区間の直後の行は訓練行と入力を共有する | 境目に**禁足区間**（embargo）を置いて捨てる |
| **リザバー状態** | `x[t]` は過去の入力すべてに依存する。検証区間より前に訓練区間を置くと、その訓練行の状態に検証区間の入力が混ざる | `rolling` なら起きない |

`blocked` は選べますが**既定にしません**。データを使い切れる代わりに、
上の 1 と 3 を作ります。「時間の向きを無視してよい」と判断した場合にだけ
使ってください。

`embargo` を省略（`null`）すると**設計行列の `first_valid`** を使います。
1 行が過去 `first_valid` 行の入力を含むので、それ未満だと検証行が訓練行と
同じ入力を持ちます（遅延線で顕著）。

## 実測（実験01、本番設定、5 レプリケート）

**テスト NRMSE はほとんど変わりません。**

| 課題 x 手法 | 単一分割 | rolling 3折 | rolling 5折 | blocked 5折 |
|---|---|---|---|---|
| delay_parity x delay_line | 1.00066 | 1.00041 | 1.00041 | 1.00052 |
| delay_parity x esn | 0.08942 | 0.08953 | 0.08952 | 0.08941 |
| delay_parity x linear | 1.00038 | 1.00038 | 1.00038 | 1.00038 |
| mackey_glass x delay_line | 0.00053 | 0.00053 | 0.00053 | 0.00053 |
| mackey_glass x esn | 0.00071 | 0.00071 | 0.00071 | 0.00071 |
| mackey_glass x linear | 0.14540 | 0.14540 | 0.14540 | 0.14540 |

**効くのは選択の安定性のほうです。** 選ばれた alpha（5 レプリケートの内訳）:

| 課題 x 手法 | 単一分割 | rolling 5折 |
|---|---|---|
| delay_parity x delay_line | `1e+02` x4, **`1e-10` x1** | `1e+02` x5 |
| delay_parity x linear | `1e+02` x3, **`1e-09` x1, `1e-10` x1** | `1e+02` x5 |

単一分割は 5 回に 1 回、**他のレプリケートと 12 桁離れた alpha** を選んでいました。
交差検証はこれを消します。遅延線の `n_lags` も `{64:5, 8:2, 1:2, 2:1}` から
`{64:5, 8:1, 1:4}` へ集約します。

**テスト誤差が変わらないのは、これらの組が元々解けていない（NRMSE ≈ 1.0）
ためです。** 解けない課題では alpha が結果をほとんど動かしません。
alpha が効く領域で使うと差が出ます。

## 何を選ぶかは変えていません

選べるのは従来どおり **alpha（全手法）と遅延線の `n_lags` だけ**です（D-08）。
ESN の構造ハイパーパラメータ（`n_units` / `spectral_radius` / `leak_rate` /
`input_scale` / `density`）は文献既定値に固定したままで、交差検証の対象では
ありません。

D-08 は「探索予算を対照より ESN 側に厚くしない」という**公平性のための決定**で、
guard_test 付きで記録されています。ESN 側も交差検証で選ぶようにすると、
Goudarzi 2014 が作ったのと同じ非対称性（ESN 側だけ最適化）が生まれます。
広げるなら、その決定ごと見直す必要があります。
