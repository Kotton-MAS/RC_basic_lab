# リザバーモデルを足す手順

**現在あるモデル** (`reservoir/` / `kind`):

| `kind` | モデル | 出典 | 特徴 |
|---|---|---|---|
| `esn` | Echo State Network | Jaeger 2001 | 既定。ランダム疎結合 + 漏れ積分 tanh |
| `deep_esn` | 深層 ESN | Gallicchio & Micheli 2017 | 層を積む。**層ごとに違う時間スケールが出る** |
| `ring` | リング結合 (SCR) | Rodan & Tino 2011 | 単一閉路 + 大きさ一定の入力重み。**ランダム性をほとんど使わない** |

01 では `--preset ring` / `--preset deep` で切り替えられる
(`experiments/01_what_is_rc/presets/`)。

**所要: 3 ファイル + テスト 1 本。**既存の実験・成果物には触らない。

**実測で確かめてある。** 使い捨ての 4 つ目のモデルを足して全テストを回したところ、
触ったのは `reservoir/<model>.py` / `protocol.py` の union / `registry.py` の
`case` の **3 ファイルだけ**で、落ちたのは生成物のモジュール地図
（`make module-map` で解消）だけだった。`experiment/` 層は 1 行も触っていない。

（2 つ目・3 つ目のモデルを足したときは 23 ファイルに及んだ。`require_esn` を
ESN 固有の経路へ入れる作業と、判別子つき union の仕組みそのものを作る作業が
含まれていたためで、**1 個目から N 個目への一度きりの費用**である。）

`experiment` 層は `Reservoir`（`reservoir/protocol.py`）だけを見ており、
`ESN` を名指ししている場所は 0 である。生成は `build_reservoir`
（`reservoir/registry.py`）の 1 本に寄せてある。

## 満たすべき面

```python
class Reservoir(Protocol):
    config:   ReservoirConfig   # meta.json と図の footnote が読む
    n_units:  int               # run が返す配列の列数と必ず一致する
    n_inputs: int
    def step(x, u, rng=None) -> FloatArray   # (N,) 自走の閉ループが使う
    def run(u, x0=None, rng=None) -> FloatArray  # (T, D_in) -> (T, N)
```

**この 5 つだけ**である。`ESN` は `W` / `W_in` / `initial_state` も公開して
いるが、**面には入っていない** —— 再帰行列を持たないモデルはいくらでもあり、
「W を持つ義務」を負わせる理由が無いためである。ESN 固有の性質を検査したい
ときは `ESN` を直接名指しする（`tests/test_reservoir.py` がそうしている）。

## 手順

### 1. 設定 dataclass を作る

`reservoir/<model>.py` に置く。値の検査は `__init__` 側で行う
（設定 dataclass は純粋なデータ保持に留める、既存の `ESNConfig` と同じ流儀）。

**`KIND` を名乗る。** YAML の `kind: deep_esn` がこれと突き合わされる。

```python
@dataclass(frozen=True, slots=True)
class DeepESNConfig:
    KIND: ClassVar[str] = "deep_esn"   # ClassVar にする (下記)

    n_units: int = 200
    n_layers: int = 3
```

`KIND` を **`ClassVar`** にするのは `dataclasses.asdict` に出さないためである。
通常のフィールドにすると `meta.json` に現れ、既存の成果物の指紋が壊れる。
判別子は「どの型を作るか」の情報であって、その型の設定値ではない。

### 2. 本体を書く

`Reservoir` の 5 面を実装する。`ESN` を継承する必要はない
（`tests/test_reservoir_registry.py::_ConstantReservoir` が、ESN を 1 行も
参照せずに面を満たせることを示している）。

**`run` は `(T, N)` を返し、`X[t]` は `u[t]` を処理した *後* の状態**である。
ここを 1 ステップずらすと、診断層（ESP・容量・リアプノフ）が静かに別の量を
測り始める。

### 3. 生成口に `case` を 1 つ足す

```python
# reservoir/protocol.py
type ReservoirConfig = ESNConfig | DeepESNConfig   # union に足す

# reservoir/registry.py
match config:
    case ESNConfig():
        return ESN(config, rng, n_inputs=n_inputs)
    case DeepESNConfig():                          # ここに 1 つ
        return DeepESN(config, rng, n_inputs=n_inputs)
```

union に足して `case` を書き忘れると、**mypy の網羅性検査が落とす**。
実行時に「なぜか ESN になっている」にはならない。

### 4. テストを書く

`tests/test_<model>.py`。最低限:

- 同一シードで 2 回作った状態がバイト一致する（再現性）
- `run` の返り値が `(T, n_units)` である
- `build_reservoir` が新しい設定でそのモデルを返す

**変異注入で赤くなることを確認する**（テストが実は何も測っていない、が起きる）。

## やってはいけないこと

- **`ESN(...)` を直接呼ぶ経路を足さない。** 生成口が 1 本であることは、
  確保軸の検査（`test_oversized_narma10_length_is_rejected_before_any_allocation`）が
  依存している前提でもある。増やすとその検査が空振りする
- **既存の成果物（`results/01..05`）を変えない。** 既定は `esn` のままで、
  乱数の引き方も変わっていない。新しいモデルは新しい設定でだけ選ばれる
- **面を広げない。** 「このモデルだけが持つ属性」が要るなら、それは
  `experiment` 層ではなくそのモデルのテストが見るべきものである

## 実験から使う

01 の設定は `ReservoirConfig` を受けるので、**YAML から選べる**:

```yaml
esn_mackey_glass:
  kind: deep_esn      # 省略すると既定 (esn)
  n_units: 200
  n_layers: 3
```

`--set` でも振れる:

**`--set` で `kind` だけを替えることはできない。** モデルを替えると設定の
**型そのもの**が変わり、前のモデル固有のキー（ESN の `density` / `activation`）は
新しい型に存在しないためである。エラーがその旨を言う:

```
ConfigError: 未知のキーです: activation, density (既知のキー: ...)。
kind: ring に無いキーです —— モデルを替えるときはセクションを丸ごと
書き替えてください (プリセットなら kind を書けば自動で置き換わります)
```

**プリセットならセクションが丸ごと置き換わる。** ローダが `kind` の変化を見て
マージではなく置換にするので、プリセット側にはそのモデルの設定を全部書く。

未知の `kind` は既知の名前を添えて落ちる（黙って既定に落ちない）。
選ばれたモデルの未知キーは従来どおり `ConfigError` になる（D-09）。

**02 / 03 はまだ ESN 固定である。** 掃引軸が `spectral_radius` /
`leak_rate` という ESN 固有の概念なので、一般化は配線の問題ではなく
「そのモデルで何を掃引するのか」という実験設計の問題になる。
05 も `to_esn()` で ESN を組んでいる。
