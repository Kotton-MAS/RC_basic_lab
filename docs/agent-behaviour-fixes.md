# エージェントの挙動の是正 — 第3版の指摘から

*作成: 2026-08-21 / 対象ブランチ: `feat/rc-basics-05` / 起点: `docs/agent-system-review-from-artifacts.md` 第3版（指摘 B-1〜B-6）*

## この文書の位置づけ

`agent-system-review-from-artifacts.md` は**成果物の側から**「何が壊れているか」を測る文書である。
本稿はその裏返しで、**エージェントの側から**「なぜそう振る舞ったか」と「何を変えれば繰り返さないか」を書く。

対象は2つ:

1. **是正の記録** — 指摘 B-1〜B-6 に対して何を入れたか（すべて実施済み・実測つき）
2. **挙動の是正案** — 同じ型の失敗を次に起こさないための、agent 定義 / hook / スキーマへの変更

**プロンプト層への追記は原則として書かない。** `CLAUDE.md` 自身が
「再発している事象への対策をプロンプト層に置かない」と定めており、
第3版 U 節が示したのは**手続き層もプロンプト層と同じ側に落ちる**という点だからである。

## 2. 失敗の型1: 同じ仕事の関数が2箇所で独立に育つ

### 何が起きたか

`experiment/freerun.py`（04）と `experiment/anomaly_ranking.py`（05）が、同じ閉形式

```
P(X >= m),  X ~ Binomial(n, 1/2)  =  Σ_{k≥m} C(n,k) / 2^n
```

を独立に実装していた。**境界の振る舞いが違い**、対の数が 0 のとき一方は `nan`、他方は `1.0` を返す。
引数検証も片方にしか無かった。どちらも記事に載る数値を作る。

### なぜエージェントがそうするか

05 を書いた回は「05 の中で完結する関数を書く」ことに最適化されている。
**04 に同じものがあるかどうかは、探しに行かない限り分からない。**
そして探しに行く動機は、探さなくても何も起きないので生まれない。

`reviewer-deletion` の観点1（同名の重複）はこれを拾うために作られたが、
**手続き層**（`CLAUDE.md` の完了条件）に置かれたため実行されず、重複が4件増えた。

### 入れたもの

- **`tests/test_duplicate_symbol_budget.py`（D-92）** — `src/` のモジュール直下の `def`/`class` 名を AST で集計し、
  現在の重複を定義箇所ごと凍結する。**新しい同名は増やせない。減らすのは自由**
- `datasets/` の5件（Protocol 実装）と `tasks/_validate` は正当なので凍結リストに残す。
  ただし**新しい同名は必ず人の判断を1度通る**

### これが効いた証拠

導入した同じセッションで、**私自身が作った重複を検出した**。
`figures_freerun.py` を分割した際に `freerun_grids.mean_std` を作り、
既存の `capacity_grids.mean_std` と衝突して赤になった。

凍結リストに追記すれば通せたが、それはラチェットを外す操作である。
**片方（空入力で `ValueError` を投げる 04 側）を捨てて1本に寄せた** ——
その挙動に依存するテストは1件も無かった。

> 設計上の要点: エラーメッセージに「**FROZEN に追記して通すのはラチェットを外す操作です**」と
> 書いてある。次に踏むエージェントが最初に読むのがこの文だからである。

## 3. 失敗の型2: 図が実測と食い違う主張をする

### 何が起きたか

FIG-1（結論をタイトルに書く）は**嘘を書ける形式**である。実例:

- 前サイクル: 21 枚のうち **5 枚のタイトルが実測と逆**だった
  （01 の PCA は「リザバー状態のほうが高次元」と書いたが実測は逆、
  4-C は「ノイズでアトラクタ領域が縮む」と書いたが実測は 49→52→55→47 でほぼ不動）
- 本サイクル: 3-C の副題が「Goudarzi の対照（正則化なし）を第4水準に足した」と書いたが、
  **こちらの動作点は `k/n_train ≤ 0.01`、先行は `k/n ≈ 0.9`** で、
  先行の対照設計を検証してはいなかった
- 4-B は参照線が無いまま「数 Lyapunov 時間」と水準の良否を主張していた

### なぜエージェントがそうするか

**結論文を書く時点で、書き手は結果を「だいたい知っている」状態にある。**
だいたい知っていることを文にするのは、実測を引き直すより安い。
そして固定文はコミット後に一度も再検証されない —— 数値が変わっても文は変わらない。

3-C の副題はより厄介な型で、**「先行の手法を実装した」を「先行の設計を検証した」と書いた**ものである。
手法（正則化なし）は再現したが、動作点（`k ≈ n_train`）は再現していない。
先行の批判を検証するには**両方**が要る。

### 入れたもの

1. **結論文を行から導く**（D-90 / D-94 / D-96）。3箇所すべてを関数にした:
   - `narma10_panel.narma10_headline` — 正則化の有無で順位が変わったかを数え直す
   - `capacity_grids.even_degree_note` — 偶数次の残存割合を数え直す
   - `freerun_headlines.valid_time_headline` — 手法間の比を数え直す
2. **水準の主張には参照線を要求する**（D-96）。4-B は参照線が引けない
   （文献値と条件が未特定）ので、タイトルを**手法間の差**に限定した
3. **FIG-2 をラチェット化**（D-96）。「文献照合図を持たない実験の集合」を凍結し、増やせなくした

### 挙動の是正案（未実施）

> **提案 A: 「先行研究の対照を再現した」と書くときは、先行の動作点を数値として記録し、検査に載せる**
>
> 3-C の副題が過剰主張になったのは、実装したのが「手法」だけで「動作点」が抜けたためである。
> 対策は文言ではなく、**先行の動作点を定数として持ち、こちらの動作点と並べて表示する**ことである。
> 3-C' の `GOUDARZI_TAPS_PER_TRAIN = 1810/2000` がその形で、図の参照線として引いてある。
>
> 一般化すると: `plotting/labels.py` の `cited()` を「出典つき文字列」から
> **「出典 + 条件（動作点）を持つ構造」**へ広げ、条件を書かない引用を描画前に落とす。
> 現在の `cited()` は出典の空文字だけを弾いており、条件の欠落は素通りする。

## 4. 失敗の型3: 飛ばしても何も起きない手順が飛ぶ

### 何が起きたか

`CLAUDE.md` の「サイクル完了時にやること」は4手順ある。実測の分かれ方:

| 手順 | 結果が目に見えるか | 実測 |
|---|---|---|
| 1. `make ci` | 赤になる | 実行された |
| 2. `reviewer-deletion` | 何も起きない | **飛んだ** |
| 3. タグを打つ | ログに出る | 実行された |
| 4. `git worktree prune` | 何も起きない | **飛んだ** |

「**走らせないことが問題である**」と明記してあってなお走らなかった。

### なぜエージェントがそうするか

タスクの完了判定は「求められた成果物ができたか」で行われる。
手順2と4は成果物を生まないので、完了判定に寄与しない。
**文言を強くしても、完了判定の構造が変わらない限り優先度は上がらない。**

### 入れたもの

- **`tests/test_cycle_hygiene.py`（D-93）** — 手順4を**状態**で判定する
  （prunable な worktree が残っていないこと）
- **手順2の結果側**を D-92 のラチェットが受け止める
  （走らせ漏れても重複そのものは止まる）
- **B-5 を `strict xfail` で入れた** —— そろえた瞬間に xpass して落ちるので、
  「直したのに検査が無効のまま」が残らない。**実際にその通りに動いた**:
  一斉再生成 → xpass で赤 → マーカーを外して通常の検査になった

> 設計上の要点: 「手順を実行したか」ではなく「**実行していれば成り立つ状態か**」を測る。
> 実行の有無を測ろうとすると「実行の記録を残す手順」がまた1つ増え、その手順が飛ぶ。

### 挙動の是正案（未実施）

> **提案 B: `reviewer-deletion` の実行漏れを、成果物の存在で見る**
>
> 第3版 M 節が挙げているとおり、`docs/削減候補-0N.md` が当該サイクルのタグ時点で
> 存在することを検査すれば実行漏れが機械で見える。
> ただし優先度は D-92 より低い（ラチェットが入れば、走らせ漏れても重複は止まる）。
>
> **提案 C: 完了手順から「成果物を生まない手順」を消す**
>
> より根本的には、手順2と4は**手順であるべきではない**。
> 手順4は D-93 が状態で見るので `CLAUDE.md` から消してよい。
> 手順2は D-92 と提案 B が入れば同様である。
> **守られない手順を書き続けると `CLAUDE.md` 全体の拘束力が下がる** ——
> squash 規約を撤回した判断と同じ論理を、ここにも適用する。

## 5. 失敗の型4・5: 検証の非対称

### 型4: 環境で変わる値を厳密一致で縛る

`wall_time` を厳密一致で照合していたため、**図のラベルを直して再生成しただけで5件が赤**になった。
直し方は「文書の数値を書き換える」しかなく、この検査は退行を1件も検出しないまま
追随修正の義務だけを生んでいた（本サイクルで3回: 87.69 → 88.0 → 95.18）。

**D-89** で比が2倍（サイズは 1.05 倍）を超える差だけを落とす形にした。
CSV 合計が 5 MB 予算に収まることは別の assert で直接測る。

> 一般則: **検査が検出する退行の件数と、検査が生む追随修正の件数を比べる。**
> 後者が多いなら、その検査は仕事をしていない。

### 型5: 他エージェントの数値主張を検証せず転記する

過去の実例: reviewer が存在しない関数を指して「100k点で 26.7 秒」と報告し、実測は **0.428 秒（62倍のずれ）**。
本サイクルでも、第3版 P 節の「3-B の偶数次が**全パネルで真っ暗**」という記述を
そのまま受け取らずに実測したところ、**セル自体は存在し**（次数2 が 398 セル、次数4 が 171 セル）、
合計容量が 0.78 と小さいために共通色スケールで 0 と見分けられない、が正確だった。
指摘の結論は正しかったが、注に書く文言は実測に基づいて変わった。

`CLAUDE.md` は「1コマンドで裏が取れるものは取る」と定めており、これは**プロンプト層**にある。

### 挙動の是正案（未実施）

> **提案 D: findings スキーマの `evidence` に「再現コマンドの実行結果」を必須にする**
>
> 現在の `.claude/schemas/findings.schema.json` は `repro_command` を要求し、
> `triage_findings.py` が「`measured` なのに `repro_command` が空」を降格する。
> ここに1段足す: **`repro_output`（実行結果の先頭数行）を必須にする**。
> コマンドを書くだけなら実行しなくても書けるが、出力は実行しないと書けない。
>
> これはプロンプト層（「裏を取れ」）から**スキーマ層**への移動であり、
> `CLAUDE.md` の「2回目以降は層を下げる」に従う。62倍の誤報告は既に2回目である。

## 7. 次の巡で測ること

第3版 U 節の一般則
（**対策を置いた層が、そのまま次に破れる場所になる**）が正しければ、
次に破れるのは**今回機械層に落とさなかったところ**である。具体的には:

   —— 一般則が正しければ、対策を置いた層は当面もつ

測り方は今回と同じで、**成果物の側から**測る（`docs/agent-system-review-from-artifacts.md` 第4版）。
エージェントの自己申告ではなく、`results/` と `src/` の実測を入力にする。

## 付録: このサイクルでラチェットが発火した回数

新設した機械が、**導入したセッションのうちに作者自身の違反を検出した**記録。

| 機械 | 発火 | 内容 | 直し方 |
|---|---|---|---|
| D-77 行数ラチェット | `figures_esp.py` 744 → 746 | FIG-1 のタイトル折り返しで2行増 | タイトルを短くした |
| D-77 行数ラチェット | `figures_capacity.py` 791 → 793 | D-94 の注を足して2行増 | 注の生成を `capacity_grids` へ出した |
| D-77 行数ラチェット | `figures_capacity.py` 791 → 792 | 3-C の副題を足して増 | 副題を `narma10_panel` へ出した |
| D-77 新規上限 | `figures_freerun.py` 606 > 600 | 4-B の結論文を足して超過 | `freerun_grids` / `freerun_headlines` へ分割 |
| D-92 同名ラチェット | `mean_std` が2箇所 | 上の分割で新しい重複を作った | 04 側を捨てて1本に寄せた |

**5回とも「上限を緩める」でも「凍結リストに追記する」でもなく、構造を直して通した。**
ラチェットが機能するのは、緩める操作がエラーメッセージの中で明示的に禁止されているからである。
