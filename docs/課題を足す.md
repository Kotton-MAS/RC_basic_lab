# 課題を 1 本足す手順

**所要: 1 ファイル + union に 2 行 + `case` を 2 つ + YAML に 3 行 + テスト。**

`docs/リザバーを足す.md` と同じ形です（D-123 で揃えました）。

## 1. 生成関数を書く

`src/rc_basics_lab/tasks/<name>.py` に純関数を 1 本。ネットワークも I/O も
持ちません（D-59）。外部データが要るなら `datasets/` が取得して渡します。

```python
def generate_narma20(cfg: Narma20Config, rng: np.random.Generator) -> TaskData: ...
```

設定 dataclass は `config/experiment01.py` に置き、**`length` を持たせます**
（`washout` 感度実験 D-19 の系列長補償が全課題に一様に効くため。
`tests/test_experiment_washout.py` が型から検査します）。

## 2. union に足して `case` を書く

| 場所 | 足すもの |
|---|---|
| `tasks/protocol.py` の `TaskConfig` | `\| Narma20Config` |
| `tasks/registry.py` の `build_task` | `case Narma20Config(): return generate_narma20(...)` |
| `config/experiment01.py` の `TaskSpec` | `\| Narma20Task` |
| `config/experiment01.py` の `with_length` | `case Narma20Task(): ...` |

`case` を書き忘れると **mypy の網羅性検査が落とします**（実行時に「なぜか
Mackey-Glass になっている」にはなりません）。

## 3. YAML に 3 行

```yaml
tasks:
  - kind: narma20
    params: {length: 8000}
    reservoir: {leak_rate: 1.0}
```

**並び順がそのまま `comparison.csv` の課題の順**になります。

## 触らない場所

- `experiment/runner.py` の `build_tasks` —— `config.tasks` を回すだけです
- `experiment/washout.py` —— 全課題を一様に伸ばします
- 図・CSV の列 —— 課題名は行の値であって列ではありません

## 手元で振る

```bash
# kind で要素を選ぶ (添字にすると並びを替えただけで意味が変わる)
uv run python main.py --experiment 01 --set tasks.narma20.params.length=2000
uv run python main.py --experiment 01 --set tasks.narma20.reservoir.n_units=50
```

プリセット（`experiments/01_what_is_rc/presets/*.yaml`）は **`kind` で
突き合わせて重なります**。差分だけ書けば足ります。

## 3-C の NARMA10 について

`experiment/narma.py` の NARMA10 は**まだこの経路に載っていません**。
`Narma10Config` が `base` に `ExperimentConfig` を丸ごと内包し、確保量の検査が
リザバーの `n_units` を読むためで、純粋な課題設定に割るのは別の変更です（D-123）。
