# 要件: rc-basics-05 実験実装 —— センサー時系列の異常検知

*記事: `rc-basics-05`「実データで使ってみる — センサー時系列の異常検知」*
*前提: `rc-basics-01`〜`04` の基盤が構築済み。基礎編の締めであり、エッジ編・メモリスタ本編への接続点*

---

## 目的

記事05の実験を実行可能にする。中心は **実データでのリザバーベース異常検知と、その正直な評価**。

**この回の性格**: 04が「リザバーが勝つ場面」なら、05は「**現実のデータで勝てるとは限らない場面**」。
異常検知は前処理と閾値設計で結果が大きく動くため、対照なしの「効きました」は無価値である。
連載を通じて積み上げた規律(公平な対照・探索予算を揃える・否定的結果も書く)を実データに適用する回。

**接続**: 「省電力な時系列処理」というRCの本来の売りが立つ応用領域であり、
連載#10(エッジ編)およびメモリスタ本編の目的地に直結する。基礎編の締めをここに置く。

## スコープ

### やること
- **データ取得・前処理層**(`tasks/anomaly.py`): 公開データセットを1〜2種。
  正常区間で学習し、異常区間を検知する設定に整形する。**前処理(正規化・窓幅)の選択を設定化**する
- **異常スコアの構成**: 予測残差ベース(ESNで1ステップ先を予測し、残差の大きさをスコアにする)を主軸。
  スコアの平滑化窓も設定可能にする
- 実験5-A: **対照込みの検知性能比較**
  - ESN(予測残差) / 遅延線+リッジ(予測残差) / persistence(残差) /
    単純統計量(移動平均・移動分散・z-score)の4系統
  - 評価: PR曲線とAUPRC(異常は稀なのでROCではなくPR系を主とする)、および
    **点調整(point-adjust)を使わない厳密評価**
- 実験5-B: **閾値の決め方の影響** —— 閾値を変えたときの検知/誤報のトレードオフ。
  「閾値を後から最適化すると誰でも高性能に見える」問題を可視化する
- 実験5-C(課題パート): **前処理と評価プロトコルで結果がどれだけ動くか**
  正規化方法・窓幅・平滑化を振り、手法間の順位が入れ替わるかを確認する
- 実験5-D(エッジ編への橋): **リザバーサイズNと検知性能の関係** ——
  Nを削っていったときに性能がどこで落ちるか(=最小構成の見積もり)

### やらないこと
- 深層学習ベースの異常検知手法(LSTM-AE, Transformer等)との比較(記事では言及に留める)
- オンライン学習・適応的閾値
- 実機・マイコンへの実装(連載#10)
- ラベルなしデータでの教師なし評価の理論的検討

## 設計判断

1. **点調整(point-adjust)評価を既定にしない**。時系列異常検知の慣例的な point-adjust は
   性能を大幅に過大評価することが知られており、ランダムなスコアでも高い値が出る。
   厳密評価を主とし、比較のため point-adjust 版も併記する場合は**その旨を明記する**
2. **異常は稀**なのでROC-AUCではなく **PR曲線・AUPRC** を主指標にする
3. **閾値は較正データで決め、テストデータでは固定する**。テスト側で最適化した閾値の結果は
   「上限の参考値」として別扱いで報告する(実験5-Bの主題そのもの)
4. **前処理は手法間で完全に共通化**する。前処理の差が手法の差に混入しないようにする
   (esn-vla-uq §11・rc-basics-03 と同じ、探索予算・条件を揃える規律)
5. データセットの選定基準を`docs/design.md`に明記する。
   **「よく使われているから」ではなく「異常の定義が明確でラベルが信頼できるか」で選ぶ**

## 入力 / 出力

- **入力**: 実験設定YAML(データセット / 前処理設定 / 手法一覧 / リザバー設定 /
  閾値決定方針 / 評価プロトコル / シード)
- **出力**:
  - `results/fig_pr_curves.png`: 4系統のPR曲線とAUPRC(**記事の主図**)
  - `results/fig_score_timeline.png`: 時系列上の異常スコアと正解ラベルの重ね描き(1例)
  - `results/fig_threshold_tradeoff.png`: 閾値と検知/誤報のトレードオフ
  - `results/fig_protocol_sensitivity.png`: 前処理・評価プロトコル別の手法順位の変動
  - `results/fig_size_vs_performance.png`: リザバーサイズNと性能(エッジ編への橋)
  - `results/anomaly.csv`, `results/meta.json`

## 制約

- CPUで完走すること
- Apache-2.0 / 個人名義

## 受け入れ条件

1. 4系統(ESN / 遅延線 / persistence / 単純統計量)が**同一前処理・同一閾値方針**で比較され、
   AUPRCが出力される
2. 点調整を使わない厳密評価が既定であり、使う場合は明示されている
3. 閾値をテスト側で最適化した場合としない場合の性能差が定量化されている
   (「後から閾値を選ぶと誰でも強く見える」ことの実演)
4. 前処理・プロトコルを振ったときに手法間の順位が入れ替わるかが記録されている
   (入れ替わるなら、それ自体が記事の主要な結論になる)
5. リザバーサイズNを削ったときの性能低下点が特定でき、連載#10で使える見積もりになっている
6. データセットのライセンスと取得手順がREADMEに記載されている
7. 図5枚が1コマンドで再生成 + pytest green
