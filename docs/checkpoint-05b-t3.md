## 0. 結論

1. **リスク2 (誰も検知できない) は回避された。** 3源すべてで ESN は乱数対照から離れている
2. **一様乱数対照の AUPRC は3源すべてで異常率に張り付いた** ——
   AUPRC が水増しされていないこと (= point-adjust を通していないこと) の実測的な裏付け
3. **どの系統が対照から離れるかは源によって入れ替わる。**
   遅延線は合成源 (2.32x) と UCR (5.96x) では離れるが、**MGAB では対照に潰れる (0.98x)**
4. **UCR では系列ごとの差が桁違いで、ESN が乱数より弱い系列が8本中2本ある** ——
   平均値だけを報告すると、この事実が消える

## 3. T4 / T5 への設計上の含意

### (a) 5-C (順位入替) の測り方 —— ユーザー確定 (2026-08-20)

**全系統の順位を記録したうえで、各系統に「一様乱数対照と区別できるか」の印を付ける。**

理由: MGAB では6系統中5系統が対照と区別できない。この群の中で順位が入れ替わっても
それは「プロトコル感度」ではなく**雑音**であり、印が無いと
「順位が入れ替わった = プロトコルに敏感」という誤った結論になる。
除外方式 (対照を超えた系統だけで順位を計算) を採らないのは、
除外の閾値をどこに置くかが新しい任意性になるため。

### (b) UCR は単一の大域設定では回らない

UCR の8系列は `train_end` が系列ごとに異なり、
系列長に対する比は **0.137〜0.405** とばらつく (ファイル名から復元される値)。
既定の `train_ratio` / `preprocess.standardize_steps` では最短系列で
「学習区間が正常保証区間を越える」「standardize_steps が学習区間の外」として**正しく拒否される**。

上記の測定は `train_ratio=0.07` / `standardize_steps=300` まで下げて全8系列を通した
—— つまり**最短系列に合わせて全系列を切り詰めている**。

**T4 / T5 の設計判断が要る**:
- 系列ごとに `train_end` を持つ源 (UCR) では、**大域の `train_ratio` ではなく
  系列自身の `train_end` から分割を導く**べきではないか
- そうしないと、長い系列の学習データを最短系列に合わせて捨てることになり、
  「N を削ると性能がどこで落ちるか」(5-D) の測定が学習量不足と混ざる

**なお実装は黙って壊れず、いずれも明示的な `ValueError` で拒否した。**
「気づかないまま無意味な数値が出る」経路にはなっていない。

### (c) 5-D (N と性能) の対象

MGAB では ESN 以外が対照と区別できないので、N を振って意味があるのは ESN だけである。
UCR では遅延線も離れている (5.96x) ため2系統で測れる。
**どの源で 5-D を回すかで、測れる系統数が変わる。**

ESN 0.9271 / 遅延線 0.9536 / persistence 0.8810 / 移動統計 0.7607 /

## 5. T4 の実測 (2026-08-21) —— 5-C の印が結論を反転させた

**オーケストレータが独立に再現した数値。**

| 指標 | 実測 |
|---|---|
| 格子点 (`normalize × input_window × score_smoothing`) | 27 |
| **順位が動いた格子点** | **21 / 27** |
| 逆転した系統対 (格子点あたりの延べ) | **46 組** |
| **うち「両方に印がある (対照と区別できる)」組** | **0 組** |
| Kendall tau-b の最小 | 0.467 |
| 印が付いた系統 | **ESN 残差 と 遅延線残差 のみ** |

### 印が無ければ逆の結論になっていた

| 系統 | 印 | 27格子点での順位 |
|---|---|---|
| `esn_residual` | **あり** | **1 (不動)** |
| `delay_line_residual` | **あり** | **2 (不動)** |
| `persistence_residual` | — | 3,4,5,6 |
| `random_control` | — | 3,5,6 |
| `input_norm_control` | — | 3,4,5 |
| `moving_statistics` | — | 4,5,6 |

**「27格子点中21で順位が入れ替わった」だけを報告すると、
「この手法比較は前処理の設定に敏感で信頼できない」という結論になる。**

実際には**検知できている2系統の順位は27点すべてで不動**であり、
46組の逆転は**すべて乱数と区別できない4系統の内部**で起きている。
つまり測っていたのは雑音の順位である。

ユーザーが確定した 5-C の方針 (全系統の順位を記録したうえで印を付ける。
除外方式は採らない) が、この反転を防いだ。**除外方式を採っていたら
「印のある2系統だけ」を見て「順位は完全に安定」と報告することになり、
今度は逆に『4系統は雑音だった』という情報が落ちていた。**

### 5-D

`n_units_at_90pct` = **100** (N=200 で 0.3935、N=100 で 0.3365 = 0.855倍、
N=50 で 0.526、N=25 で 0.319、`saturated=False`)。全24行が `n_train=4900` で揃っている。

### UCR の `train_end` 問題の扱い

**(b) を採用。ただし散文ではなく機械化した** ——
5-D の入口に「全系列が同じ `n_train` で回っていること」という**正の条件**を置いて
`ValueError` にする (D-80)。源の名前で分岐しない (D-71) ので、
将来 UCR の分割を系列ごとに導く実装が入れば**自動的に条件が満たされて回る**。
5-C は UCR でも回る。

(a) を採らなかったのは、`dataset.train_ratio` の意味が全源で変わり
**5-A の既定の数値が動く** (= 上の §1 の表を測り直すことになる) ため。

|---|---|---|---|
| `esn_residual` | **0.1602 ± 0.0130** | **2.83x** (15/15, p=3.1e-05) | **あり** |
| 遅延線 / persistence / 移動統計 / 入力ノルム / 一様乱数 | 0.056〜0.057 | 1.00x | なし |

異常率 0.0555 に一様乱数が張り付く。5-C は 27点中23点で順位変動・逆転62組。
5-D は `n_units_at_90pct = 100` (全24行 `n_train=14800`)。合計 wall time **231.4 秒** (予算 900)。

### 注意: 「両方に印がある 0 組」は本番設定では**構造的に0**である

`fig_protocol_sensitivity.png` の右パネルは
「逆転した系統対 62 組 / うち両方に印がある 0 組」と表示する。

**本番 (MGAB) では印が付く系統が ESN の1つだけなので、
『両方に印がある組』は組み合わせとして存在しえない。** つまりこの 0 は
経験的な発見ではなく**数学的な必然**である。

一方、合成源では印が2つ (ESN・遅延線) 付くので、同じ 0 は
「逆転は印のある2系統を避けて起きた」という**経験的な発見**になる (§5)。

**同じ「0 組」でも意味が違う。** 記事で使うときは、印の数を併記しないと
読者は前者を後者と読む。より正確な言い方は
**「実データでは6系統中1系統しか検知できていない」**であり、
それ自体がこの回の結論である。

**対応案** (T5 のスコープ外): 右パネルの凡例に印の付いた系統数を出すか、
印が1つ以下のときは「両方に印がある組」の系列を描かずに
「印のある系統が1つしかないため定義されない」と注記する。
