日付: 2026-09-02

## 0. この装置の強みはモデルではなく「対照」である

先に立ち位置をはっきりさせておきます。ESN の実装は世界中にあります。
このリポジトリが持っていて他があまり持っていないのは、**主張の隣に対照を置く仕組み**のほうです。

- 事前宣言した格子を**全件報告**する（選ばない）
- シャッフル代替・一様乱数対照・遅延線を**必ず並べる**
- 対応のある符号検定で「差」ではなく「印が付くか」を見る
- 成果物のバイト不変・シードの分離・`decisions.yaml` の guard\_test

**研究のネタは「装置が主役になる問い」に寄せるのが一番効きます。**
つまり「うちの ESN が速い/強い」ではなく、**「その主張、対照を置いても残りますか」**の側です。
以下はその方針で並べました。

---

## 1. トポロジ —— 追試ではなく「交絡を剥がす対照の梯子」【最優先】

### 先行研究の現状（重要）

**「スケールフリーは記憶容量に効くか」は未解決の問いではなく、すでに主張がある問いです。**

- [Hub nodes integrate memory and prediction in reservoir computing (Nonlinear Dynamics, 2025)](https://link.springer.com/article/10.1007/s11071-025-12162-4)
  —— BA / ER / WS / 実脳ネットワークを比較し、**BA が広い ρ の範囲で MC が優れる**、
  ER にハブを人工的に埋め込むと改善する、BA のハブを弱めると劣化する、と報告。
  ρ > 1 でも性能を保つ、とも。
- [A small-world topology enhances the echo state property and signal propagation (Neural Networks, 2019)](https://www.sciencedirect.com/science/article/abs/pii/S0893608019300115)
- [The architecture of dynamic reservoir in the echo state network (2012)](https://pubmed.ncbi.nlm.nih.gov/23020466/)

したがって **「BA を足して MC を測る」は発見の実験になりません**（追試になります）。
追試そのものに価値はありますが、それだけだと弱い。

### では何をやるか —— 交絡を1つずつ剥がす

D-131 で既に 2 つ記録してあります。**実は 4 つあります。**

同じ密度で ER と BA を比べると、同時に動くもの:

| # | 交絡 | 実測（N=200） |
|---|---|---|
| 1 | **次数分布**（ハブの有無） | BA の最大入次数 29 / 平均 4 に対し、ER は 31 / 20 |
| 2 | **相互結合率** | BA・WS は辺が対称（`W[i,j]` と `W[j,i]` が必ず対）、ER は独立 |
| 3 | **自己ループ** | ER は 17 本前後、BA・WS は 0 本 |
| 4 | **ρ 正規化との相互作用** | ρ を 0.9 に揃えても、ハブに固有値が集中する行列と一様な行列では**ノードごとの実効ゲインの分布が違う**。「同じ ρ」は「同じ動作点」ではない |

4 は D-131 にまだありません。`spectral_profile` が `spectral_gap` を出すようになったので、
**測れます**（ハブ型はギャップが大きくなるはず）。

### 梯子（この順で回す）

| 水準 | 何を変えるか | 何が言えるか |
|---|---|---|
| ER | 基準 | — |
| ER を対称化 | 交絡 2 だけ | 相互結合の効果 |
| ER の対角を 0 に | 交絡 3 だけ | 自己ループの効果 |
| **BA を次数保存ランダム化** | **次数分布だけ残す** | ← **これが鍵** |
| BA | 全部 | 先行の条件 |

**4 段目が本命です。** BA のグラフを取り、**次数列を保ったまま辺を張り替える**
（configuration model / double edge swap）。ハブの「次数分布」は保たれ、
「優先的選択が作った相関構造」だけが壊れます。

- ここで BA の優位が**残る**なら、効いているのは次数分布（＝先行の主張が支持される）
- **消える**なら、効いていたのは次数分布ではなく BA の生成過程が作る別の何か

これはネットワーク科学では標準の帰無モデルですが、**RC のトポロジ論文では
まず置かれていません**。置けること自体がこの装置の売りに合っています。
`networkx.double_edge_swap` を dev のオラクルにして、本体は numpy で 20 行程度です。

### 測るのは MC ではなく IPC の分解

先行は MC + 予測ホライズンで測っています。こちらは **IPC の次数×遅延分解**が出せます。
問いを1段細かくできます:

> ハブが買っているのは**線形記憶**か、**非線形容量**か、それとも**遅延の深さ**か

先行の abstract が open に挙げている "task-dependent performance trade-offs" が
まさにここです。`ipc_linear` / `ipc_nonlinear` / `mc_effective_delay` の 3 本を
トポロジ別に出すだけで、先行が答えていない形の答えになります。

## 2. その前に —— 乱数の引き順がペア比較を壊しています【前提整備】

**実測しました**（`reservoir/esn.py` の構築順）。

```
136-137: W_in を引く          ← トポロジより前
145:     build_mask(...)       ← トポロジによって消費する乱数の個数が違う
146:     values = rng.uniform(-1, 1, (N, N))   ← ここが後ろにある
```

同一シードで ER と BA を作ると:

| | 結果 |
|---|---|
| `W_in` が一致するか | **する**（トポロジより前に引くため） |
| 共通する辺 115 本で `W` の値が一致するか | **しない** |
| Ring が乱数を消費するか | **しない**（構造が決まりきっているため 0 個） |

つまり **ER と BA は「マスクだけが違う 2 つの行列」ではなく、
「マスクも重みの値も違う 2 つの行列」**です。Ring に至っては消費 0 なので、
`values` の引き始めがさらにずれます。

これは正しさの問題ではありません（どれも妥当な実現値です）。問題は**統計です**:

- トポロジの効果は、重みの実現値の分散と同じくらいの大きさになることがあります
- いまの設計だと**ペアが組めない**ので、その分散を差で潰せません
- このリポジトリの統計はペアが前提です（符号検定、D-115 の列ごとの照合）

### 手当て

`values` の抽選を `build_mask` の**前**へ移すか、`SeedStream` に `TOPOLOGY` を足して
マスクだけ別ストリームから引く。どちらでも、同一シードで
**「同じ重み行列を、違うマスクで切り出す」**が成立します。

`SeedStream` は末尾に足す規約（`_STREAM_INDEX` のコメント）があるので、
`TOPOLOGY = 4` を足すのが素直だと思います。**既存の成果物は動きます**が、
これは意図した変更として通す側です（トポロジ研究の前提が変わるので、
やるなら本実験を始める前に）。

### ついでに: レプリケートの設計を入れ子にする

いまは「シード = リザバー1本」です。トポロジ比較では分散が 2 種類あります:

- **グラフの実現値の分散**（同じ BA でも引くたびに違うグラフ）
- **重みの実現値の分散**（同じグラフでも重みが違う）

**M グラフ × K 重み**の入れ子にすると、どちらが支配的かを分解できます。
「BA が良い」と言うとき、グラフ間分散がトポロジ間差より大きければ主張は立ちません。
`3 × 3 = 9` でも、いまの `n_replicates = 3` と同じ計算量です。

## 3. N のスケーリング —— 物理リザバーは小さい N に住む

いまの結果はすべて固定 N（200 か 50）です。物理実装で必ず聞かれるのは
**「素子を増やしたらどう伸びるか」**のほうです。

すでに材料は揃っています:

- 保存則 `IPC_total ≤ N` と、比を主軸にした 3-B' の図
- §2.2 の実測 —— **ノイズ 0.1 では N を増やすほど `IPC/N` が下がる**（0.125 → 0.073）

ここに**トポロジ軸を掛ける**と、問いが一段良くなります:

> トポロジの順位は N に依存するか。BA の優位（あるとして）は N を下げても残るか

先行は大きめの N で測っています。**小さい N（25〜100）で順位が入れ替わるなら、
それは物理リザバーにとって先行より重要な結果**です。
入れ替わらないなら「規模によらない」という、これはこれで使える結論になります。

---

## 4. ノイズ下で順位が入れ替わるか ——【メモリスタ編への橋。いちばん論文の形】

これが個人的には**一番面白い問い**だと思います。

トポロジ最適化の文献はほぼすべて**ノイズなし**で行われています。
一方で物理リザバーには素子ばらつき・熱雑音・ドリフトが必ず載ります。

> **ノイズなしで選んだ最適トポロジ／最適 ρ は、ノイズ下でも最適か**

- 最適点が動かない → 文献の最適化はそのまま移植できる（安心して使える結論）
- **動く** → **ノイズなしで最適化した設計は物理素子に移らない**（強い否定的結果）

どちらに転んでも書けます。そして必要なものは全部あります:

- `state_noise` は既存の軸
- トポロジは新しい軸
- 容量測定は `diagnostics.csv` に長形式で出る
- 04 の 3 態マップは「ノイズ 4 桁で領域がほとんど動かない」を既に測っている

**いまなら YAML を数行足すだけの実験です。** 逆に言うと、
この実験が安いのは今の設計のおかげなので、そこは回収しに行く価値があります。

なお 04 の実測（ノイズを 4 桁振っても自走の可否がほとんど動かない）と、
03 の実測（同じノイズが容量を大きく削る）は**ずれています**。
このずれ自体が問いです —— 容量が削れても自走が壊れないのはなぜか。

## 5. NARMA10 の宿題の閉じ方

保留中の件（N=200 + leak=1.0 で逆転する）は、先行と繋げると据わりが良くなります。

[Dynamical Anatomy of NARMA10 Benchmark Task (Kubota & Nakajima)](https://deepai.org/publication/dynamical-anatomy-of-narma10-benchmark-task)
が、**NARMA10 は位相空間に不安定領域を持ち、入力範囲と初期値の選び方で発散する**、
だから**公平な比較を妨げるベンチマークである**、と論じています。

これは記事 03 §3.1 の実測（「宣言した分布の内側でも発散する。定数入力 0.5 なら 33 ステップ」）と
**独立に同じ現象に到達しています**。引ける先行があるので引いたほうが強い。

そのうえで、こちらの主張は先行と別のものになります:

| | 先行 | こちら |
|---|---|---|
| NARMA10 の問題 | **課題側の**動作点（入力範囲）で結果が変わる | **手法側の**動作点（N・リーク率）で勝敗が変わる |
| 根拠 | 位相空間の解析 | IPC 分解（容量の 2/3 が要求されていない非線形へ） |

**2 つ合わせると「NARMA10 は両側の動作点に敏感で、単独の数値に意味がない」**という
一段強い主張になります。宣言した格子を全件出す方針（修正指示 T8）とも噛み合います。

## 6. 測定器そのものの妥当性検査【地味だが効く】

トポロジの結論を出す前に、**道具のほうを疑っておく**価値があります。

### 6-1. 他実装との突き合わせ（最優先）

`docs` が既に [kubota0130/ipc](https://github.com/kubota0130/ipc) を参照実装として挙げています。
**同じ状態行列を両実装に食わせて IPC が一致するか**を1回やっておく。

一致すれば「自前実装で測った」という最大の弱点が消えます。
ずれれば、それはそれで最も価値のある発見です。
`networkx` をオラクルにした D-122 と同じ形なので、規律にも合っています。

### 6-2. IPC の T 依存はトポロジによって違うか

`capacity_length.csv`（T = 1e5〜1e6）は既にありますが、ER 1 条件だけです。
**ハブ型は飽和に必要な T が長いかもしれません。** もしそうなら、
同じ T で ER と BA を比べた文献は BA を過小評価していることになります。
これは §1 の結論を左右するので、**§1 より先に**確かめたほうが安全です。

### 6-3. サロゲート閾値の効き

99 パーセンタイル × 100 本という設定が、測定値をどれだけ動かすか。
02 の `abs_tol` 感度掃引（9 条件で境界が 1 格子も動かなかった）と同じことを
容量側でもやっておくと、「閾値をいじって作った図ではない」が言えます。

## 7. 統計の設計で先に決めておくこと

- **効果量を先に宣言する。** 「MC が何倍違えば意味があるか」を実験前に置く。
  IPC の測定誤差（レプリケート間 s.d.）は既に出ているので、
  それより小さい差は最初から見ないと決めてしまう
- **多重比較。** トポロジ 4 × ρ 6 × リーク 3 = 72 セル。
  「どこかで有意」は必ず出ます。**事前に主仮説を 1 つ**（例: ρ=0.95・leak=1.0 での BA vs 次数保存ランダム化）
  に決めて、残りは探索として報告する
- **対応のある検定を使い続ける。** §2 を直せばトポロジ間でもペアが組めます

---

## 8. やらないほうがいいこと

- **モデルをこれ以上増やしてから対照を作る、の順序。** モデルを1つ足すと
  比較の面が N 倍に増えます。**対照の梯子（§1）を先に作って、そこへモデルを流す**
- **LSTM / Transformer との比較。** 学習コストと精度のどちらを揃えるかで
  結論が変わる非対称な比較で、記事 01 で既にそう書いています。装置の強みも出ません
- **「うちの ESN が強い」型の実験。** 探索予算の非対称さ（#3 の 5 章）が
  そのまま自分に返ってきます

## 10. 出し方について

促進したいのが「RC 研究そのもの」なら、いちばん再利用される成果物は
**結果ではなく対照のプロトコル**だと思います。

> リザバーに関する「X が効く」という主張には、
> (a) 次数保存ランダム化 (b) シャッフル代替 (c) 探索予算をそろえた素朴な対照
> のどれかを隣に置く

これを日本語で書いた文書と、それを実行できるリポジトリが対で存在する、
というのが一番効く形です。`docs/guide/` と core/series の切り出しが
既にその準備になっています。

論文にするなら §4（ノイズ下で最適が動くか）が最も形になりやすく、
記事にするなら §1（先行の主張に帰無モデルを当てる）が最も読まれると思います。
