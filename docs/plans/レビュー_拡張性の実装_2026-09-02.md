## 1. `meta.json` から判別子が全部消えている **[最重要]**

### 実測

```python
ESNConfig(topology=RingTopologyConfig())
# -> {"activation":"tanh", ..., "topology": {}}          ← 空
ESNConfig(topology=ErdosRenyiConfig(0.1))
# -> {"activation":"tanh", ..., "topology": {"density":0.1}}
RingConfig()
# -> {"bias_scale":0.1, ..., "spectral_radius":0.9}      ← kind なし
```

コミット済みの `results/meta.json` を検索すると **`kind` という文字列が 1 件もありません**。
`reservoir.kind` も `task.kind` も `topology.kind` も入っていない。

BA トポロジで 01 を実際に回して確かめました:

```json
"reservoir": {"activation":"tanh","bias_scale":0.1,"input_scale":0.5,
              "leak_rate":0.3,"n_units":60,"spectral_radius":0.9,
              "state_noise":0.0,"topology":{"m":2}}
```

`{"m": 2}` から BA だと**推測**はできます。しかし:

- `RingTopologyConfig` はフィールドが 0 個なので **`{}`** になり、情報がゼロ
- `RingConfig`（SCR モデル）と `ESNConfig` は、`topology` / `activation` の**有無**でしか区別できない
- 課題も同じで、`{"params": {"beta":0.2,"exponent":10,...}}` から Mackey-Glass だと当てる

### なぜ今これが問題か

`config/_dump.py::as_plain_mapping` は**リストの要素にだけ** `kind` を書き、単一フィールドには
書きません。その理由は docstring にこうあります —— 「**既存の `meta.json` を動かさないため**」。

その判断は、モデルが 1 種類しかなく `kind` が飾りだった頃は正しかった。
**いまは前提が消えています**:

1. このリファクタの主題は「`kind` を振ること」そのもの
2. `density` → `topology` の変更で **`meta.json` はどのみち動いた**（`ea17c14` で指紋を取り直し済み）。
   守ろうとしていた不変性はもう無い
3. `as_plain_mapping` は**テストからしか呼ばれていません**（`tests/wiring.py` ほか 4 箇所）。
   `meta.json` を書くのは `collect_meta_for` → `dataclasses.asdict` のほうです

つまり **「読み直せる形」を作ったのに、永続する記録のほうは読み直せない形で書かれている**。
シリアライザが 2 本あって、弱いほうが成果物に使われている状態です。

`results/` は「読者に届く唯一のもの」（CLAUDE.md）で、`meta.json` はその素性の記録です。
スケールフリーの実験を何本か回して results をアーカイブしたとき、
**どれがどのトポロジだったかが成果物から復元できません**。

### 手当て

`meta.json` の設定ダンプを `as_plain_mapping` 経由にし、`in_sequence` の条件を外して
**判別子を持つ dataclass には常に `kind` を書く**。1 行の変更です。

`meta.json` は動きますが、これは**意図した変更**として指紋を取り直す側です
（D-74 の「なぜ変わったかをコミットメッセージに書く」経路）。
むしろ、記録が読み直せるようになったことを guard で固定する価値があります:

> `meta.json` の設定ブロックを読み直すと、元の設定と等しい dataclass が復元できる

これは round-trip の性質なので、変異注入（`kind` の書き出しを外す）で確実に赤くできます。

## 2. `diagnostics/topology.py` がどこからも呼ばれていない

312 行 + テスト一式が入りましたが、**実験からの呼び出しは 0 件**です。
`require_graph` も定義だけで使用箇所がありません（`registry.py` の定義と `protocol.py` の
docstring 内の言及のみ）。したがって **`results/**` にトポロジ由来の行は 1 行もありません**。

動作そのものは正しく、期待どおり構造を弁別します（N=200 で実測）:

| トポロジ | density | 最大入次数 | 裾指数 | C | L | sigma |
|---|---|---|---|---|---|---|
| Erdos-Renyi | 0.102 | 31 | 1.39 | 0.192 | 2.01 | 1.64 |
| **Barabasi-Albert** (m=2) | 0.020 | **29** | **2.32** | 0.039 | 3.43 | 2.20 |
| **Watts-Strogatz** (k=4, β=0.1) | 0.020 | 6 | 2.03 | **0.355** | 6.06 | **11.21** |
| Ring | 0.005 | 1 | nan | 0.000 | 100.00 | nan |

BA は同じ密度の WS に比べて最大次数が 5 倍、WS は sigma が 11 —— 指標として効いています。
リング の L = 100 = N/2 も理論どおり。**道具は完成しているのに、配線だけが無い**状態です。

`docs/guide/診断を足す.md` の手順 3 が「実験から呼ぶ。結果を `scalar_rows(...)` に渡せば
`diagnostics.csv` に出る」なので、その 1 手順を W 族に対して実行すれば終わります。
自然な置き場所は 03（容量と同じ状態行列を作っている）か、新しい 06 です。

**いま配線しておく理由**: `diagnostics.csv` の `condition_id` は「振った軸だけ」を並べる形式
（D-118）です。トポロジは軸ではないので、いま条件キーに現れません。
トポロジを振る実験を作る段になって「条件キーにトポロジをどう書くか」を決めることになり、
**それは形式の変更 = 全実験の CSV が動く**（D-118 が明示的に警告している事態）。
配線を後回しにするほど、この決定が高くつきます。

## 3. 掃引が入れ子の設定に届かない —— スケールフリー実験の本命がまだ書けない

```
ESN の軸: ['bias_scale','input_scale','leak_rate','n_units','spectral_radius','state_noise']
  topology.m      -> ValueError: ESNConfig は持っていません
  m               -> ValueError
  density         -> ValueError
```

`numeric_axes` は「**フィールドが軸である**」という良い設計ですが、
数値でないフィールド（= 入れ子の設定）を軸から外すので、`topology` の中には入れません。
`density` は `topology` に移ったので、**分離前にできた `density` の掃引もできなくなっています**。

これが効くのは今後の中心的な実験です:

- 「m を 1→8 に振ると MC はどう動くか」（BA のハブの強さ）
- 「β を 0→1 に振ると格子からランダムへ連続的に動かしたとき、どこで自走が安定するか」（WS）

いまはどちらも掃引機構では書けず、専用のループを書くことになります。
**それはこのリファクタが消したはずの形**です。

### 手当て（軽いほうから）

**(a) ドット記法を 1 段だけ許す。** `with_axis(config, "topology.m", 4)` を
`dataclasses.replace(config, topology=replace(config.topology, m=4))` に展開する。
`numeric_axes` も 1 段潜って `topology.m` を返す。`--set` が既にドット経路を扱っているので、
**同じ記法**にできます。深さ 1 段に限れば実装は 20 行程度、`require_axes` の
エラーメッセージもそのまま使えます。

**(b) トポロジは軸ではなく「条件」として扱う。** `kind` を替える掃引は
`topology` の格子（`[{kind: ba, m: 1}, {kind: ba, m: 2}, ...]`）を回す別の口にする。

(a) と (b) は排他ではなく、**(a) が「同じ kind の中で数値を振る」、(b) が「kind をまたぐ」**
を担当する形が素直だと思います。どちらを採るにせよ、`condition_id` にトポロジを
どう書くかは §2 と同じ決定なので、あわせて決めるのが安いはずです。

## 4. トポロジ間の比較に、密度以外の交絡が 3 つある

実測で確認しました:

| トポロジ | 自己ループ | 隣接行列 |
|---|---|---|
| Erdos-Renyi | **16 本**（N=200, d=0.1） | 非対称 |
| Barabasi-Albert | 0 本 | **対称** |
| Watts-Strogatz | 0 本 | **対称** |
| Ring | 0 本 | 非対称 |

モジュールの docstring は

> どのトポロジも**有向グラフとして扱い、自己結合を消さない**

と書いていますが、これが当てはまるのは ER だけです。BA / WS は構成上、自己ループも
非対称性も作れません（無向アルゴリズムなので）。文としては「ER は自己結合を残す。
BA / WS は無向なので自己結合を持たず対称になる」が実態です。

実害は**実験設計側**にあります。同じ nominal density で ER と BA を比べると、
差は次数分布だけでなく

1. **相互結合率**（BA は W[i,j] と W[j,i] が必ず対で存在、ER は独立）
2. **自己ループの有無**（自己ループはスペクトル半径の正規化と実効的な漏れに直接効く）

も同時に動きます。「スケールフリーだから MC が高い」と言うには、この 3 つを分けた
対照が要ります（例: ER を対称化した対照、BA の対角を埋めた対照）。

**いま必要なのはコードの修正ではなく、docstring を実態に合わせることと、
この交絡を `decisions.yaml` に 1 件残しておくこと**だと思います。
記事を書く段になって「BA が勝った」を言うときに、必ずここを聞かれます。

このリポジトリの規律（「手書きの表は写経を忘れた時点で嘘になる」）が
そのまま当てはまる場所です。

### 5-2. `diagnostics.csv` が 01 と 05 に無い

02 / 03 / 04 にはあります（5,167 / 2,007 / 5,449 行）。01 は `state_pca` と `unit_activity` を、
05 は ESN を回しているので、出せるスカラはあるはずです。
**意図的に外したのか、まだなのか**が記録から読めませんでした。
D-118 の rule は「診断が返すスカラは…`diagnostics.csv` へ」と全称で書いてあるので、
外したのなら理由を、まだなら残件として書いておくと次の人が迷いません。

### 5-3. DeepESN の検査メッセージがトポロジ非依存になっていない

`nominal_density` を使って一般化されているのは正しいのですが、メッセージが

> density が低すぎます —— n_layers を減らすか **density を上げて**ください

のままです。BA なら上げるのは `m`、WS なら `k` です。
`require_axes` / `require_esn` が「持っている軸はこれ」と直し方まで言う水準に
揃えるなら、ここも `topology` の `kind` に応じた語にしたいところ。

### 5-4. `--set` でトポロジの `kind` を替えられない

```
ConfigError: ...topology.barabasi_albert: 未知のキーです: density (既知のキー: m)
```

これは `kind` を替えると型が変わるという既知の性質（`リザバーを足す.md` に記載）が
トポロジにも及んだもので、**動作としては正しい**（エラーが直し方まで言っている）。
ただし新しいガイドのどこにも書かれていないので、`docs/guide/` に 1 行あると親切です。
プリセットなら通ることは実測で確認しました（BA と WS を混ぜた 01 が完走）。

### 5-5. `_watts_strogatz` の張り替えが O(N²)

各辺の張り替え先を毎回リスト内包で作っているので、N が大きいと効きます
（N=200 なら 8 万回で無視できる。N=2000 で 800 万回）。
いま直す必要はありませんが、**大きい N でトポロジを振る日が来たら最初に当たる場所**です。

## 6. 着手順の提案

| 順 | 項目 | 理由 |
|---|---|---|
| 1 | **`meta.json` に `kind` を書く**（§1） | 1 行 + 指紋の取り直し。**放置するほど「素性の分からない成果物」が増える** |
| 2 | **トポロジ診断の配線**（§2） | §3 の `condition_id` の決定とセットなので、先に形を決めておきたい |
| 3 | **入れ子の軸**（§3） | ここまでで「BA の m を振って MC を測る」が設定だけで書ける |
| 4 | §4 の docstring 修正と交絡の記録 | コード変更なし。記事を書く前に必要 |
| 5 | 5-1 / 5-2 / 5-3 | 小さい |

1〜3 を終えると、**当初の目的（スケールフリーなリザバーの解析）が
「診断を 1 本書く」ではなく「YAML を 3 行書く」で回るところまで届きます**。
