## 0. 要旨

3-C の ESN が遅延線に負けている件は、**リザバーの性質ではなく動作点の未探索**による
可能性が高い。原因は `n_units` ではなく **`leak_rate: 0.3`** である。

この指示は「勝つ設定を探して差し替える」ものでは**ない**。
`narma.base.esn_mackey_glass` の1点だけを報告している現状を、
**あらかじめ宣言した格子の全セルを併記する**形に変える。
選択は行わないので D-08(構造 HP を検証分割で選ばない)は保たれる。

| N | ρ | leak | ESN NMSE (mean ± sd) |
|---:|---:|---:|---|
| 50 | 0.9 | 0.3 | **0.2673 ± 0.0079**(現行の本番設定) |
| 50 | 0.9 | 0.6 | 0.2074 ± 0.0118 |
| 50 | 0.9 | 1.0 | 0.1726 ± 0.0146 |
| 50 | 0.95 | 1.0 | 0.1750 ± 0.0150 |
| 50 | 1.0 | 1.0 | 0.2078 ± 0.0330 |
| 200 | 0.9 | 0.3 | 0.2474 ± 0.0110 |
| 200 | 0.9 | 0.6 | 0.1648 ± 0.0057 |
| 200 | 0.9 | 1.0 | **0.0514 ± 0.0133** |
| 200 | 0.95 | 1.0 | 0.0564 ± 0.0117 |
| 200 | 1.0 | 1.0 | 0.0686 ± 0.0079 |

対照(現行 `narma10.csv`): 遅延線 = 0.1538、線形 = 1.0297。

読み取り:

- **N=200 単独では逆転しない**(0.2474。遅延線より 7% 良いだけ)。
- **leak=1.0 単独でも逆転しない**(N=50 で 0.1726。遅延線 0.1538 に届かない)。
- 逆転するのは **N=200 かつ leak=1.0** の組み合わせのときで、そのとき
  遅延線の約 3 分の 1 の NMSE になる。
- ρ の効きは leak・N に比べて小さい(0.9〜1.0 で 0.05→0.07)。

**注意**: この表はコンテナ側の別環境(Linux / 別ビルドの numpy)で得たもので、
記事に載せる数値ではない。本番で回し直した値だけを記事に書く。

## 2. なぜ leak が効くのか(リポジトリ内の既存実測で説明できる)

`results/03_capacity/capacity.csv` の 3A_mc_sweep(N=200、σ_u=0.1、3 レプリケート平均)より:

| ρ | leak | mc_total | mc_effective_delay | ipc_total | ipc_linear | ipc_nonlinear |
|---:|---:|---:|---:|---:|---:|---:|
| 0.9 | 0.3 | 20.12 | 49.62 | 37.71 | 13.47 | 24.24 |
| 0.9 | 0.6 | 21.19 | 22.06 | 77.30 | 19.99 | 57.31 |
| 0.9 | 1.0 | 29.47 | 16.29 | 117.76 | 29.38 | 88.38 |

leak を下げると **記憶は深くなるが容量そのものが痩せる**。
leak=0.3 の重心遅延は約 50 ステップで、NARMA10 が要求する 10 ステップを大きく
超えている。一方で非線形容量は leak=1.0 の 3.6 分の 1 しかない。
NARMA10 の目標は `u[t-1] * Σ_{i=1..10} y[t-i]` という**10 ステップ以内の積項**なので、
容量予算を深さに振るのは無駄で、非線形容量に振ったほうが効く。

つまり第3章の容量の枠組みが**事後の説明ではなく事前予測として**効く形になる。
(絶対値は動作点が違うので 3-C と直接比較しない。読むのは leak に対する順序だけ。)

現行 config の `esn_mackey_glass` には
「NARMA10 は連続値入力の回帰課題で、漏れ積分が効く点で MG と同型だから」
というコメントで leak=0.3 が継承されている。この類推が NARMA10 では
成り立っていない、というのが今回の発見である。

## 3. 作業内容

### T8-1 宣言格子の追加

`experiments/03_capacity/config.yaml` の `narma` セクションに新しいサブセクションを追加する。

```yaml
narma:
  # ... 既存 ...
  # 3-C'' (D-xx): ESN の動作点格子。**全セルを報告する**。
  # 検証分割で選ぶのは alpha だけで、n_units / leak_rate は選ばない (D-08)。
  esn_grid:
    n_units_grid: [50, 200]
    leak_rate_grid: [0.3, 1.0]
    # ρ・input_scale・bias_scale・density は base.esn_mackey_glass のまま動かさない。
```

`base.esn_mackey_glass` は**そのまま残す**。(50, 0.3) のセルがそれと一致することを
テストで突き合わせる。

### T8-2 実行経路

`experiment/narma.py` の ESN 経路を、1 セルではなく `esn_grid` の直積で回すようにする。
各セルは独立に `run_task(base, entry, plan0=...)` を通す(D-31 の経路を変えない)。
セル間の集約(best-of / min など)は**書かない**。

### T8-3 CSV スキーマ

`results/03_capacity/narma10.csv` に列を追加する:

- `n_units`(delay_line / linear の行は 0)
- `leak_rate`(同上 0.0)

`method` は `esn` のまま(セルの識別は上の 2 列で行う)。
既存の列順は変えず末尾に足す。

### T8-4 決定の記録

`.claude/decisions.yaml` に新規 D-xx を起票する。記録すべき論点:

1. 格子は**事前宣言・全件報告**であり、検証分割による選択ではない(D-08 を破らない)。
2. **D-39 は取り消さない**。N=50 は先行(0.107 / 0.16)と規模をそろえた**参照行**として
   残す。N=200 は「規模を上げると何が起きるか」を見る**追加行**であって、
   参照値との比較には使わない。
3. leak=0.3 は MG からの継承であり、3A_mc_sweep の実測(§2)がその類推を否定した。
   leak=1.0 を並べるのはその検証のためである。
4. 探索予算の非対称は**解消しない**。遅延線は n_lags 5 点 × α 13 点 = 65 点、
   ESN は各セル α 13 点。セルを増やしても各セルは独立に報告されるので、
   1 セルあたりの予算は 13 点のまま。この数字を design.md に機械可読で持たせる
   (記事の公平性の記述がテストで守られるようにする)。

### T8-5 guard test

- `esn_grid` が YAML に宣言した通りのセル数で `narma10.csv` に現れること
  (セル数 × レプリケート数の行数)。
- `(n_units=50, leak_rate=0.3)` のセルが `base.esn_mackey_glass` と一致すること。
- コード中にセル間の集約が無いこと(best-of を書けないことを示す構造テスト、
  あるいは「全セルが CSV に残っている」ことで代替してよい)。
- α 格子が 01 と共有されている既存テストはそのまま通ること。
